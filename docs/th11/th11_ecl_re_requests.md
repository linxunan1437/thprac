## 2. Q1 当前 sub：索引还是指令指针？

**✅ 结论：是「当前指令的绝对地址（指针）」，不是 sub 索引。**（与 th13 同构；th15–18 才是索引）

- 读取表达式：`ip = *(u32*)(T + 0x04)`（`T` = 线程/脚本上下文，`T = *(u32*)(H + 0x1030)`（主线）= `H+8`）；`ip == 0` ⇒ 线程已结束。
- 类型 / 取值范围：`u32` 绝对 VA，落在**某个已加载 ECL 缓冲内**；**不存在 `0..count-1` 这一层索引**。
- 证据：解释器分发头 `0x45B890` 把 `[edi+4]` 当指针读 `ins[0]`/`ins[4]`/`ins[6]`/`ins[0xA]`；`T+4` 的写入点全部是地址（`0x4113C9` 设主线 sub = `FindSubByName(res,name)`、`0x45D283` 逐指令推进 `+= ins.size`、`0x45B8E9` `ret` 恢复调用者 ip、`0x45BAC2` `goto` 重定位、`0x45D2B4` 线程结束置 0）。
- **本作特有**：`call`(0x0B) / `async`(0x0F) 的目标是**内嵌在指令 `+0x14` 起名字串**，运行期经 `FindSubByName`（`0x45DB10`）解析为 `table[i].+4+0x10`。
- 详见报告 §2（含反汇编片段与写入点表）。

## 3. Q2 sub 表：索引 → 名字/起始

**✅ 结论（与 th13 逐字段一致）：**

```text
mgr   = *(u32*)0x4A8D7C            // 全局 ECL 管理器
res   = *(u32*)(mgr + 0x64)        // ECL 资源对象（访问器 GetRes @0x40D0B0）
count = *(i32*)(res + 0x08)        // GetResCount @0x40D0A0
table = *(u32*)(res + 0x8C)        // GetTable @0x4106D0
name_i  = *(char**)(table + i*8)   // 项 +0 = 名字 char*
start_i = *(u32*)(table + i*8 + 4) + 0x10   // 项 +4 = 数据基址 ⇒ 首指令 = +4+0x10
buf_slot = *(u32*)(res + 0xC + slot*4)      // 已加载 ECL 文件缓冲数组
```

- `GetSubName` @ `0x40D070`、`GetResCount` @ `0x40D0A0`、`GetRes` @ `0x40D0B0`、`GetTable` @ `0x4106D0`。
- 加载器 = `FUN_0045D900`（SCPT 魔数 `0x54504353`、版本 1、头尺寸 @`+6`、sub 数 @`+0x10`、偏移表 @`0x24+hdr`、名字串区紧随其后）；表**按名字字典序**维护（故可二分）。
- **线索解答**：`[ENEMY_MGR_PTR(0x4a8d7c)+0x64]+0xC` 确认是 `THSectionPatch` 的 ECL 数据区（`res+0xC` = 文件缓冲数组首址），**其上一级 `res+0x8C` 就是 sub 表** ✅。
- 详见报告 §3（加载器 / 二分查表 / `.ecl` 头实测）。

## 4. Q3 函数栈

**🟡 结论：存在显式可遍历栈（骨架确认；精确遍历步长未完全定案）。**

- 栈基址 `T+8`；栈指针 `SP = *(u32*)(T+0x1008)`（**字节**偏移，`0` = 顶层/空栈）；`SP` 上限 `0x1000`。
- 帧内容 `{ 调用时 T+0（时间, float）；调用者当时的指令地址（= 调用者 T+4） }`；`ret`(0x0A) 以**固定 8B** 回退并恢复二者。
- 压帧 = `FUN_0045B610`（`call` 0x0B case → `0x45BA10`）；弹帧 = `ret` case @ `0x45B8BD`；`async`(0x0F) 经 `FUN_0045D7A0` **另起线程**（不压栈）。
- ⚠️ **实参与帧同处一段区间**（实参在帧之上），逐帧上溯需知每帧的实参数（`call` 的 `ins[+0xB]`），**完整遍历规则未定案**；本判定**不使用**函数栈。
- 详见报告 §4。

## 5. Q4 主线宿主捕获点

**✅ 结论：捕获点 = `0x4204A3` / `0x4205E0`，命中时 `EAX` = 主线宿主 H。**

- 两条站点前一条指令均为 `call 0x4108F0`（分别在 `0x42049E` / `0x4205DB`），参数为 `"main"`（`0x494258`）；`FUN_004108F0(name)` 末尾 `0x410AD8: mov eax,ebp` ⇒ **返回 EAX = H**；下一条指令均为 `call 0x41A6D0`（5B）⇒ **5B EHOOK 合适**。
- 宿主构造 = `FUN_004111C0`（`edi` = 对象、栈参 = 脚本名、`ret 4`、返回 EAX = H）；其中 `H+0x102C = res`、`T+4 = FindSubByName(res, name)`（`0x4113C9`）。
- **静态兜底（无需钩子）**：`H = *(u32*)( *(u32*)( *(u32*)0x4A8D7C + 0x68 ) )`（宿主链表头节点；节点 = `H+0x11A4` = `{+0 H, +4 next, +8 prev}`）。⚠️ `FUN_004108F0` 有 7 个调用点，只有两处传 `"main"` ⇒ 兜底仅在 main 最先创建时成立，**推荐仍用捕获点**。
- 对照总括里 TH15 的角色：`0x43BBC8/0x43D48E/0x43D6BE` ↔ 本作 `0x4204A3/0x4205E0`。
- 详见报告 §5。

## 6. Q5 解释器命中点与寄存器语义

**✅ 结论：`0x45D2A3` 语义已厘清（并更正 requests 原文）。**

- **函数**：`FUN_0045B860`（入口 `0x45B860` / RVA `0x5B860`，体 `0x45B860`–`0x45D2C4`）。入参：`EAX` = 线程 T；栈参 = 帧增量 float。返回 `0` = 本帧到此为止、`−1` = 脚本结束。
- **分发行**：`0x45B890`（`mov esi,[edi+4]` / `mov al,[esi+0xa]`）；opcode `> 0x58` → `0x45D269`（对 `[T+0x1014]` = H 的**虚调用**）；`≤ 0x58` → 字节映射 `0x45D3BC` → 跳表 `0x45D2C8`。映射核实：`0x0A`(ret)→`0x45B8BD`、`0x0B`(call)→`0x45BA10`、`0x0C`(goto)→`0x45BAC2`、`0x0F`(async)→`0x45B912`。
- **命中点 `0x45D2A3`（覆盖 2B = `D9 1F` = `fstp dword ptr [edi]`）**：位于「下一条指令时间未到 → 累加本帧时间并返回」**尾部**，**不是**分发头；命中寄存器 **`Edi` = 线程 T**，写完 `T+0` 后 `ret 4` 返回 0。
- **能否作每帧稳定触发点**：**否**（只在等待态命中，且对所有线程/所有宿主都命中）。**推荐**：不新增 VM 钩子，改在 `0x4204A3`/`0x4205E0` 抓 H，再在 IGI 渲染（帧间稳定态）读 `T = *(u32*)(H+0x1030)`、`ip = *(u32*)(T+4)`。
- **调用链**：`FUN_0045D420`（`0x45D420`，遍历 `H+0x1030` 线程链，`call 0x45B860`）← `0x411ABB` / `0x411D43`（宿主每帧更新）/ `0x438B06`。
- 详见报告 §6。

## 9. Q8/Q9 练习跳转补丁影响 + 段落判定口径

> **Q9（段落判定口径）**：**已定案为「路过式 checkpoint（latch）」**（见总括 §6 Q9）——经过白名单函数即置值、不在表内 no-op（不回退 `main`）。

**Q8 ✅ 结论：`ECLJump` 不影响 sub 判读；分支关亦成立。**

- `ECLJump`（`thprac_th11.cpp:992-996`）只写 6 个 dword（`size=0x18`，低 16 位 opcode = `0x0C` = **`goto`**，`ins[0xA]=0xFF` 任意难度、`ins[+0x10]=dest-start`、`ins[+0x14]=delay`），与本作指令头布局逐字段吻合。
- `goto`（case `0x0C` @ `0x45BAC2`）**只改 `T+0`（时间）与 `T+4`（ip）**，不触碰 sub 表、不触碰「当前 sub」的旁路字段。
- `ECLSatoriJump`（`:1034`）是 `ECLJump` + 按机体的分支跳转，同为纯 `goto` 补丁。
- ⚠️ **stage 4 分支**：st4 的 6 份变体脚本（`stage4c00{a,b,c}` / `stage4c01{a,b,c}`，sub 名 `BossCard*`）是**独立 ECL 文件**，经 `ECLHelper::SetFile(ord)`（= `res+0xC+ord*4`）选择（thprac 在 st4 boss 段用 `SetFile(2)`/`SetFile(3)`）。`ECLJump` 的偏移是**相对该槽位文件**的（写侧纪律问题）。
  ⇒ **读侧天然兼容**：`res+0x8C` 表是**所有已加载文件的并集**（每加载一个文件 `res+8 += n` 并把其 sub 插入同一排序表），故**无论走哪条分支**，`T+4 → 名字` 的映射都正确，无需特判。
  ⇒ 已列入 §10 真机验证清单。

**Q9 ✅ 结论：路过式 checkpoint（latch）。**

- **当前 sub 如何取**：`T = *(u32*)(H+0x1030)`（主线线程 = `H+8`）→ `ip = *(u32*)(T+4)` → 经 `table[i].+4+0x10` 区间表反查得 sub 名 → 白名单命中则置当前段落，未命中 no-op。完整流程见报告 §10.3。
- **每 checkpoint 登记 1 个入口 sub**（= warp(`ECLJump` dest) 落点所进入的那个 sub，**含 `async` 落点**）。
- ⚠️ **本作特有注意（async）**：本作段落子脚本**大量经 `async`(0x0F) 起新线程**（离线实体 `stage01.decl:2254`：`@MainSub00() async; … @MainSub06();`），这些线程挂在同一宿主 H 的线程链 `H+0x1030` 上。`H+4` 会被本帧最后执行过的线程覆盖，语义不稳定 ⇒ **推荐读 `H+0x1030`**（语义稳定）；若需覆盖 async 落点，可**遍历 `H+0x1030` 线程链**（节点 `{+0 线程, +4 next}`）对每个线程各做一次 latch 判定。**两种取法均需真机确认**（报告 §10.5/§13）。
- ⚠️ **未定论项**：**段落入口白名单尚未枚举**（`../exes/ecl_dump/th11/` 20 份 `.decl` 素材已在机，可离线枚举）；替代方案 = 复用 `THStageWarp`/`THPatch` 里的硬编码入口偏移（报告 §10.4）。
