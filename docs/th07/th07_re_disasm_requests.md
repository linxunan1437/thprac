## 0. 本轮需要的是"地址 + 判据"，不是 hook

与以往的需求不同：**本次不需要在游戏里挂钩子，只需要给出可以跨进程读取的静态地址与判定条件。**

因此对交付物的硬性要求：

1. 必须是**进程内固定地址**（`.data` / `.bss` 段里的全局量，或"全局指针 + 固定偏移链"），不能是栈上/寄存器里的临时值。因为读取方在**另一个进程**里，只能 `ReadProcessMemory(base + RVA)`。
2. 必须给出**取值语义**：等于什么表示"暂停中"/"正在回放"，以及**不在该状态时的取值**。
3. 必须能在**任意时刻**安全读取（读失败会被当作"不计时"，不会崩，但会造成漏计）。若某地址只在特定阶段有效，请特别标注。
4. 若需要**两级指针**（全局指针 → 偏移 → 字段），请给出完整链路与每一级的存在性条件（指针为 0 时怎么办）。

## 1. "未暂停"标志（最关键）

### 目标
需要判断"**游戏自身的暂停菜单是否处于打开状态**"。

注意区分：这**不是** thprac 自己的 `THPauseMenu`（那是注入后的 thprac 界面），而是游戏原生的暂停菜单——玩家按 Esc / 暂停键打开的那个。

### 需要确认的问题
1. 游戏把"暂停菜单是否打开"存在哪个地址？
   - 是全局字节/整数，还是某个全局指针指向的对象里的字段？给出地址或**指针链**。
2. 取值语义：什么值表示"暂停菜单已打开"？"未打开"时是什么值？（TH06 的对应量是 `*(BYTE*)0x69D4BF == 0` 表示未打开，可作参考。）
3. 在**非游玩状态**（标题画面、菜单、选人、结算）下这个地址是什么值？我们需要确保这些状态下判据也不会误判为"正在游玩"。
4. 该地址在**整个进程生命周期内**是否一直有效可读？

### 背景参考（thprac 已确认的邻近事实）
- **gamemode 已确认**：`Supervisor` 结构基址 `0x575950`（`thprac_th07.cpp:15` 的 `Supervisor* SUPERVISOR = (Supervisor*)0x575950;`），其 `gamemode` 字段在 `+0x154`，即绝对地址 **`0x575AA4`**，取值 `== 2` 表示关卡进行中。
  - `thprac_th07.cpp:710` 有 `DWORD gameState = SUPERVISOR->gamemode; if (gameState == 2) {...}`。
  - `thprac/src/thprac/thprac_th07.h:212/243` 有对应的 `static_assert`（结构体布局已被校验）。**`Supervisor` 的完整结构体定义可直接在 `thprac_th07.h` 里查到** —— 如果暂停标志也是 `Supervisor` 的字段，请优先在 `Supervisor` 里找。
- **建议切入点**：thprac 已经挂了"防止暂停/恢复时 desync"的钩子
  `th07_unpause_prevent_desync`（`thprac_th07.cpp:2091`，地址 `0x403481`）。
  它正好在"**恢复游戏**"的执行路径上 —— **它附近（或它读取的对象里）极可能就有暂停状态量**。建议从这个地址向回/向前追调用链。
- 另外 thprac 还有 `th07_midi_pause`（`thprac_th07.cpp:2040`，`0x44CA0C`），但那是 BGM 相关，与暂停状态无关（见下面"已排除"）。

### 已排除的错误线索（不要重走）
- ⚠️ **`0x575a87` 不是暂停标志**。`thprac_th07.cpp:2041` 的上下文是
  `if (g_adv_igi_options.th06_pauseBGM && *(BYTE*)(0x575a87) == 2)`，
  判断的是 **BGM 类型 == 2**（配合"暂停时暂停 BGM"这个选项），与暂停状态无关。
- 用 capstone 扫过 `th07.exe` 整个 `.text` 段：**没有任何指令直接引用 `0x575AA4`**（游戏是通过 `Supervisor` 指针 + 偏移访问的，所以"搜绝对地址"这条路对 TH07 无效）。
- `GameManager.__byte_93DC / __byte_93DD`（`0x62F64C` / `0x62F64D`）在 `0x4018a6` 附近被当布尔使用，形态上疑似 TH06 `isInGameMenu` / `isInRetryMenu` 的对应物，但 TH07 的 `GameManager` 尾部布局与 TH06 不同（多一个 `full_shottype`，中间夹了 `flags_93D8`）。**未经证实，不要直接采用**，但可作为候选线索去验证。

## 2. "非 replay"标志

### 目标
需要判断"**当前是否正在播放 replay（回放）**"。

注意区分：thprac 里已有的 `CheckReplay()`（`thprac_th07.cpp:433` 附近）是**读取 replay 文件里的参数**（`ReplayLoadParam`），用于练习模式回放工具，**不是**"实时是否在回放"这个状态量。不要拿它当答案。

### 需要确认的问题
1. 游戏把"当前处于 replay 播放中"存在哪个地址？给出地址或指针链。
2. 取值语义：什么是"正在回放"，什么是"正常游玩"？（TH06 的对应量是 `*(byte*)0x69BCBC == 0` 表示非 replay。）
3. 该状态从**何时开始**置位、**何时清除**？（例如：从 replay 菜单选定播放时置位，回到标题时清除。）
4. 在 replay 播放期间，"gamemode == 2"（关卡进行中）是否也为真？我们需要确认两个判据是**独立**的（否则单靠 gamemode 无法排除回放）。
5. 该地址在任意时刻是否都有效可读？

### 背景参考
- **建议切入点**：thprac 有 replay 菜单相关的钩子 `th07_rep_menu_3`（`0x45b2c1`，见 `thprac_th07.cpp` 里 `th07_rep_menu` 系列）。从该地址反查它读写/设置的是哪个全局量，很可能就是 replay 状态或其来源。
- TH07 的 replay 管理器在 thprac 里**尚未**定出指针（TH11/TH12 有 `REPLAY_MGR_PTR`，TH13/TH18/TH20 也有，TH07 没有）。如果定位过程中先找到 replay 管理器指针，请一并记下。
- 验证方法参考：`%APPDATA%\ShanghaiAlice\th07\replay\` 下的 replay 文件可直接在游戏里播放，便于做三态验证（见 §3）。

## 3. 三态验证（必须做，且必须记录）

任何候选地址在被采纳前，都必须通过下面的验证。**请在报告里附上实际观测值。**

在"正常游玩 / 打开暂停菜单 / 播放 replay"三种状态下，分别读取候选地址并记录取值：

| 状态 | 期望 |
| --- | --- |
| 标题画面 / 菜单 / 选人 | gamemode 判据不成立（不计时） |
| 关卡内正常游玩 | 三个判据**全部成立**（计时） |
| 关卡内按 Esc 打开暂停菜单 | pause 判据不成立（暂停不计时） |
| 播放 replay 期间 | replay 判据不成立（回放不计时） |

三种状态下取值必须**互不相同**且符合各自判据，否则该地址不可用。

thprac 侧已有一段现成的三态探针做法可以参考：`docs/gametime/gametime_plan.md` §1.7 提到的调试读数面板，会直接显示三个标志位的原始读数。

## 4. 交付格式

请回填到本文档（在对应问题下补「结论」小节），或另附报告 `docs/th07/th07_re_disasm_report.md`。要求：

- 若某个量**确认不存在**（例如游戏没有独立的 replay 状态量），也请明确说明，并给出替代方案（例如"用 X 处的 Y 值组合判断"）。
