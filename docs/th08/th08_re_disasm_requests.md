## 0. 本轮需要的是"地址 + 判据"，不是 hook

与以往的需求不同：**本次不需要在游戏里挂钩子，只需要给出可以跨进程读取的静态地址与判定条件。**

因此对交付物的硬性要求：

1. 必须是**进程内固定地址**（`.data` / `.bss` 段里的全局量，或"全局指针 + 固定偏移链"），不能是栈上/寄存器里的临时值。因为读取方在**另一个进程**里，只能 `ReadProcessMemory(base + RVA)`。
2. 必须给出**取值语义**：等于什么表示"暂停中"/"正在回放"，以及**不在该状态时的取值**。
3. 必须能在**任意时刻**安全读取（读失败会被当作"不计时"，不会崩，但会造成漏计）。若某地址只在特定阶段有效，请特别标注。
4. 若需要**两级指针**（全局指针 → 偏移 → 字段），请给出完整链路与每一级的存在性条件（指针为 0 时怎么办）。

## 1. "未暂停"标志（最关键）

### 目标
需要判断"**游戏自身的暂停菜单是否处于打开状态**"。

注意区分：这**不是** thprac 自己的 `THPauseMenu`（注入后的 thprac 界面），而是游戏原生的暂停菜单——玩家按 Esc / 暂停键打开的那个。TH08 因为"永夜异变"的设定，暂停菜单里还有"暂停时间/继续"等选项，逻辑可能比 TH06/TH07 略复杂。

### 需要确认的问题
1. 游戏把"暂停菜单是否打开"存在哪个地址？
   - 是全局字节/整数，还是某个全局指针指向的对象里的字段？给出地址或**指针链**。
2. 取值语义：什么值表示"暂停菜单已打开"？"未打开"时是什么值？（TH06 的对应量是 `*(BYTE*)0x69D4BF == 0` 表示未打开，可作参考。）
3. TH08 的暂停菜单是否有**多个子状态**（如暂停中、暂停菜单里选了"重开"、暂停菜单里的"继续"确认框）？若有，请给出能覆盖所有"非正常游玩"子状态的判据。
4. 在**非游玩状态**（标题 / 菜单 / 选人 / 结算 / 剧情对话）下这个地址是什么值？我们需要确保这些状态下判据也不会误判为"正在游玩"。
5. 该地址在**整个进程生命周期内**是否一直有效可读？

### 背景参考（thprac 已确认的邻近事实）
- **gamemode 已确认**，而且是一组相邻的三个 dword（像一个小状态机）：

  | 常量名 | 地址 | 出处 |
  | --- | --- | --- |
  | `GAMEMODE_ADDR` | `0x17CE8B0` | `thprac_th08.cpp:27`，用于 `:1066`、`:2842` |
  | `GAMEMODE_NEXT_ADDR` | `0x17CE8B4` | `thprac_th08.cpp:28`，用于 `:2990` |
  | `GAMEMODE_PREV_ADDR` | `0x17CE8B8` | `thprac_th08.cpp:29` |

  取值 `== 2` 表示关卡进行中（`thprac_th08.cpp:1066`: `DWORD gameState = GetMemContent(GAMEMODE_ADDR); if (gameState == 2) {...}`）。
  **既然 gamemode 是一组相邻字段，暂停状态很可能也在附近或同属一个更大的状态结构 —— 建议优先扫 `0x17CE8xx` 一带。**
- thprac 在 `thprac_th08.cpp:18-30` 已有一批确认过的地址常量，可直接用作定位参照：
  `SHOTTYPE_ADDR=0x164d0b1`、`DIFF_ADDR=0x160f538`、`INPUT_ADDR=0x164d528`、`GUI_ADDR=0x160f428`、`STAGE_PENDING_INTERRUPT=0x4ea290`、`SPELLCARD_ID_ADDR=0x4EA678`、`MISS_COUNT_ADDR=0x164CFA4`、`BOMB_COUNT_ADDR=0x164CFA8`、`DEATHBOMB_COUNT_ADDR=0x164CFAC`。
- **建议切入点**：thprac 已经挂了"防止暂停/恢复时 desync"的钩子
  `th08_unpause_prevent_desync`（`thprac_th08.cpp:3107`，地址 `0x40421a`）。
  它正好在"**恢复游戏**"的执行路径上 —— **它附近（或它读取的对象里）极可能就有暂停状态量**。建议从这个地址向回/向前追调用链。

### 已排除的假线索（不要重走）
- ⚠️ **`0x17CE88F` 不是暂停标志**。`thprac_th08.cpp:3004` 的上下文是
  `if (g_adv_igi_options.th06_pauseBGM && *(BYTE*)(0x17CE88F) == 2)`，
  判断的是 **BGM 类型 == 2**（配合"暂停时暂停 BGM"这个选项），与暂停状态无关。
  （注意它与 gamemode 只差 `0x21` 字节，很容易误认。）
- ⚠️ **`th08_pause_test` 这个变量名是误导**。它出现在 `thprac_th08.cpp:2974`：
  `int32_t th08_pause_test = ((int32_t*)pCtx->Esp)[6];`
  实际是**从栈上取的参数**，在 `:2991` 与 `retn_addr` 一起用来**区分 BGM 命令的调用点**
  （`if (retn_addr == 0x4480ed && th08_pause_test == 0x434d08)`），
  与"暂停"完全无关。**它不是一个地址，也不是暂停标志。**
- 用 capstone 扫过 `th07.exe` 的 `.text` 段：没有指令直接引用 `0x575AA4`（同类游戏通过指针 + 偏移访问全局结构）。**TH08 很可能同理 —— 直接"搜绝对地址 `0x17CE8B0`"这条路可能无效**，请从指针/结构体入手。

## 2. "非 replay"标志

### 目标
需要判断"**当前是否正在播放 replay（回放）**"。

注意区分：thprac 里已有的 `CheckReplay()`（`thprac_th08.cpp:822` 附近）是**读取 replay 文件里的参数**（`ReplayLoadParam`），用于练习模式回放工具，**不是**"实时是否在回放"这个状态量。不要拿它当答案。

### 需要确认的问题
1. 游戏把"当前处于 replay 播放中"存在哪个地址？给出地址或指针链。
2. 取值语义：什么是"正在回放"，什么是"正常游玩"？（TH06 的对应量是 `*(byte*)0x69BCBC == 0` 表示非 replay。）
3. 该状态从**何时开始**置位、**何时清除**？
4. 在 replay 播放期间，`GAMEMODE_ADDR == 2` 是否也为真？我们需要确认两个判据是**独立**的（否则单靠 gamemode 无法排除回放）。
5. 该地址在任意时刻是否都有效可读？

### 背景参考
- **建议切入点**：thprac 有 replay 菜单相关的钩子 `th08_rep_menu_3`（`0x46ec2e`，见 `thprac_th08.cpp` 里 `th08_rep_menu` 系列）。从该地址反查它读写/设置的是哪个全局量，很可能就是 replay 状态或其来源。
- TH08 的 replay 管理器在 thprac 里**尚未**定出指针（对照：TH11/TH12 有 `REPLAY_MGR_PTR`，TH13 `0x4c22c8`、TH18 `0x4cf418`、TH20 `0x1c60fc`）。如果定位过程中先找到 replay 管理器指针，请一并记下 —— 这能一并惠及其余作品。
- 验证方法：`%APPDATA%\ShanghaiAlice\th08\replay\` 下的 replay 文件可直接在游戏里播放，便于做三态验证（见 §3）。

## 3. 三态验证（必须做，且必须记录）

任何候选地址在被采纳前，都必须通过下面的验证。**请在报告里附上实际观测值。**

| 状态 | 期望 |
| --- | --- |
| 标题画面 / 菜单 / 选人 | gamemode 判据不成立（不计时） |
| 关卡内正常游玩 | 三个判据**全部成立**（计时） |
| 关卡内按 Esc 打开暂停菜单 | pause 判据不成立（暂停不计时） |
| 播放 replay 期间 | replay 判据不成立（回放不计时） |

三种状态下取值必须**互不相同**且符合各自判据，否则该地址不可用。

thprac 侧已有一段现成的三态探针做法可以参考：`docs/gametime/gametime_plan.md` §1.7 提到的调试读数面板，会直接显示三个标志位的原始读数。
