## 1. Q1 —— 运行期取「当前指令 ip」并换算成「相对文件缓冲的偏移」

### 1.1 ip 的来源（✅ 引自 th10 报告 §2、§6.1，未重跑）

```text
H     = 主线 ECL 宿主（捕获点 0x41829E / 0x41849E，命中 EAX = H；或静态兜底 *(u32*)(*(u32*)(mgr+0x58))）
T     = *(u32*)(H + 0x1030)          // 主线内嵌线程（≡ *(u32*)(H+4)）
ip    = *(u32*)(T + 4)               // ★ 当前（下一条待执行）指令的【绝对地址】；0 = 线程已结束
```

- `[T+4]` 是**指针语义**（报告 §2.1 三处独立证据：解释器按指针读 `[ip+0]/[ip+4]/[ip+6]/[ip+0xA]`；`FindSubByName` 返回值直接写进 `T+4`；`goto` 把 `ins+ins[+0x10]` 写进 `T+4`）。**本作不存在「当前 sub 索引」这一层**（与 th13 同构，与 C 代 th15–18 不同）。
- 写入点（报告 §2.2）：`0x40DA1F`（spawn `main`）、`0x44FB83`（逐指令 `+= ins.size`）、`0x44E238`（`ret`）、`0x44E40F`（`goto`）、`0x44FBB0`（线程结束置 0）。

### 1.2 换算成「相对文件缓冲的偏移」（✅ 本次核实）

```text
mgr   = *(u32*)0x477704                                   // 脚本管理器（thprac 名 ENEMY_MANAGER_PTR）
res   = *(u32*)(mgr + 0x54)                               // ECL 资源对象
base  = *(u32*)(res + 0xC + slot*4)                       // ★ slot 的文件缓冲基址
off   = ip - base                                         // ★ 相对文件缓冲的字节偏移
```

**证据链（三条独立）：**

1. **加载器写侧**（报告 §3.2）：`FUN_00450220` 内 `mov [ebx + eax*4 + 0xc], ecx`（`ebx` = res、`eax` = slot），紧随其后 `cmp dword ptr [ecx], 0x54504353`（"SCPT"）⇒ **传进来的缓冲从 `SCPT` 起算**，故 `缓冲内偏移 == 文件内偏移`。
2. **thprac 自己的读侧**（`thprac/src/thprac/thprac_games.h:710-726`）：

   ```cpp
   void SetBaseAddr(void* addr) { mPtrToBuffer = (uint8_t*)addr;
       VFile::SetFile((uint8_t*)(*(uint32_t*)addr), 0x99999); }        // slot 0
   void SetFile(unsigned int ordinal) {
       VFile::SetFile((uint8_t*)(*(uint32_t*)(mPtrToBuffer + ordinal*4)), 0x99999); }
   ```

   而 `THSectionPatch` 传的是 `GetMemAddr(0x477704, 0x54, 0xC)`，展开（报告 §3.5）= `res + 0xC` ⇒ **`*(u32*)(res+0xC)` 就是 slot 0 的缓冲基址**，thprac 的 `SetPos(off)` 即写 `base + off`。
3. **交叉验证**：`THStageWarp` 的 `start`（如 st1 `0x9cb8`）与 `dest`（如 `0x9f40`）离线解析后**都落在 `stage01.ecl` 的真实指令边界上**（§2.2、§3.1），说明 warp 常量与「文件偏移」是同一坐标系。

### 1.3 必须按文件槽位区分吗？—— 对本章程行**不需要**（🟡 有证据）

- `stage01.decl:2` = `ecli { "default.ecl"; }`（st2–st7 同）⇒ **slot 0 = 该关主文件 `stageNN.ecl`，slot 1 = `default.ecl`**（与 `checkpoint_entry_backfill_workflow.md` §3.1 的槽位约定一致）。
- `THStageWarp`/`THPatch` 的**章节**跳转全部走默认槽（`SetBaseAddr` 不 `SetFile`）⇒ 本表 18 行 **一律 slot 0**。
- ⚠️ 若日后把 **boss 行**也改成偏移，则必须把 **slot 号**一并登记 —— 本表不含 boss 行，见 §7。（**2026-10-18 订正**：本作 **无独立 boss 文件 / boss 槽** —— 7 关 `ecli` 只有 `default.ecl`，boss sub 与 `main` **同在 slot 0 的 `stageNN.ecl`**；见报告 §5A.3。）

### 1.4 基址固定吗？—— **不固定**（🟡）

`res` 与各 slot 缓冲都在堆上（`FUN_0040D260` `malloc(0x1098)` 造 res；加载器 `malloc(count*8)` 造 sub 表、另分配文件缓冲）。**必须每帧沿指针链重读**，不可缓存地址（与 th15 正式实现的「不缓存任何指针」一致，见 `logger_progress.md` §4 第 8 条）。

## 2. Q2 —— 坐标系一致性核实

### 2.1 判据

`THStageWarp` 的偏移是「离线手工解码 `.ecl` 得到的指令地址」（总括 §2.1）。运行期 `ip` 是**运行期缓冲的绝对地址**。两者可比 ⟺ **`ip − base == 文件偏移`**。§1.2 已证 `base` 即 slot 0 缓冲起点；故可比。**本次用离线解析独立复核**（下 §2.2）。

### 2.3 顺带发现的两条判据（🟡 有证据，供回填/自检复用）

1. **「落点是段落入口」还是「时间跳跃」的判据**：设 `t_land` = 落点指令的 `time`、`at_frame` = `ECLJump` 的第 4 参。
   - `t_land > at_frame` ⇒ 解释器在落点**等待** ⇒ ip 会停在落点 ⇒ **该 jump 是段落入口**；
   - `t_land ≤ at_frame` ⇒ 落点指令立即执行、ip **跑穿** ⇒ 该 jump 是**段内时间跳跃**（不是入口）。
   - 依据：`goto` 语义 = `T+0 = ins[+0x14]`（绝对赋值）+ `T+4 = ins + ins[+0x10]`（报告 §9.2）；解释器等待条件 = 「指令 `time > T+0` → 累加帧增量后返回 0」（报告 §6.1；本次以 `capstone` 复核 `0x44E1C9: fcomp` / `0x44E1CD: test ah,0x41` / `0x44E1D0: jp 0x44FB96`，为 `t > T+0` 分支）。
2. **`ECLJump` 不移动任何指令地址**：它只在 `start` 处**就地覆写** 6 个 dword（`size = 0x18` 的 `goto`），不重排、不搬运；`goto` 只改 `T+0`/`T+4`，不触碰 sub 表（报告 §9.2）。⇒ **所有偏移恒定**，warp 前后同一偏移指向同一指令（唯一例外：`start` 之后被 `goto` 的 `size` 吞掉的那几条指令，见 §5.3）。

### 3.2 需要标注的两处「不是直抄」

1. **`ST4 前半 #2`（唯一必须修正的行）**：`dest = 0xe048` 但 `t_land = 110 ≤ at_frame = 409` ⇒ `goto` 把 `T+0` 赋值成 409 后，落点及其后 6 条指令（t=110）**立即执行**，ip 一路跑到 `0xe0c0`（t=410）才停 ⇒ **`0xe048` 在帧边界上永远观测不到**。两种处理：
   - **(a) 登记可观测点** `0xe0c0`（本表取值）：**只有 1 帧窗口**（下一帧 `T+0=410` 即执行并前进到 `0xe148`）。仿真：`T+0=409 → ip=0xe0c0`；`T+0=410..429 → ip=0xe148`。
   - **(b) 登记 `dest` 并改用区间匹配**（推荐，见 §4.3）：`ip ∈ [0xe048, 0xe918)`（`0xe918` = `ST4 前半 #3` 的落点）⇒ `0xe0c0`/`0xe148` 都命中，无窗口风险。
2. **3 行 p1（`ST1/ST2/ST3 前半 #1`）**：p1 段**没有 ECLJump**（warp 模式 1 的 `case 1: break;`），段落入口 = 关卡正常开始 ⇒ **语义入口 = `main` 首指令**（`0x9c90`/`0xb708`/`0xca20`），但首指令 `t=0` 会**立即执行**、不可观测；**可观测锚点 = `main` 的第一条 `time > T+0`（T+0=0）**，即 `0x9cb8`/`0xb764`/`0xca7c`（`t=160`）。**这三处恰好就是该关章节补丁位**（`THStageWarp` 的 `start`）——因为 thprac 正是把 `goto` 插在「关卡开始时第一个等待点」上。⇒ 好处：**warp 到 p2..pN 时该处已被换成 `ecl_time = 0` 的 `goto`，会立即执行、不会停留**，故不会误判为 p1（同帧内自纠，§5.2）。

### 3.3 反面核对：`ST6` 的「第二条 jump 不是入口」（🟡 供自检复用）

`ST6 #2/#3/#4` 的第二条 `ECLJump(0xfb20→0xfb40, at=2953/2408/1703)` 落点 `t ≤ at_frame` ⇒ 按 §2.3 判据是**段内时间跳跃**，不是入口；CSV 现填的 `MainSub2/#3/#5` 取的是**第一条** jump 的落点（`0xed70`/`0xf63c`/`0xf8c4`）——**与 CSV 一致、与「取最后一条」的字面规则不一致**。⇒ 回填/自检脚本应改用 §2.3 判据（「最后一条**落点会等待**的 jump」）而不是「最后一条 jump」。本表 18 行的「最后一条」恰好都是入口（已逐条验 `t_land > at_frame`），不受影响。

## 5. Q5 —— 风险

### 5.1 风险 A：**boss 跳转把 ip 落到章节锚点上**（🟡 已实测，最重要）

把 `THPatch`（boss 行）全部 `ECLJump` 按 §2.3 判据算出**可观测 ip**，与本章程锚点求交 ⇒ **5 处撞点**：

| boss 行 | warp | 可观测 ip | 撞上的章节行 |
| --- | --- | --- | --- |
| `ST1 MID1` | `0x9cb8→0xaf74` (at=2200) | `0xafd8` | **`ST1 后半 #1`**（锚点 `0xafd8`） |
| `ST1 MID2_EN` | 同上 | `0xafd8` | 同上 |
| `ST1 MID2_HL` | 同上 | `0xafd8` | 同上 |
| `ST4 MID1` | `0x14a64→0x14a84` (at=3600) | `0x14aa4` | **`ST4 前半 #1`**（主线程第一条等待点） |
| `ST4 MID1` | `0xf8ec→0xf900` (at=3600) | `0xf930` | **`ST4 后半 #1`**（`MainSub4` 线程内） |

- **成因**：thprac 的章节跳转与 boss 跳转共用同一个「章节闸门」偏移（st1 `0x9cb8`、st4 `0x14a64`），boss 跳转只改 `at_frame`；`t_land ≤ at_frame` 时 ip 会继续跑到下一个等待点，正好是「后半第一节」的锚点。
- **性质**：这**不是 ip 偏移方案特有的问题**，而是**既有 sub 名口径同源的已知问题** —— `logger_progress.md` §6（2026-10-16）已记录：th16 真机上「很多关卡后半第一节的 checkpoint 实为增援章节，主线程在中boss 存活期间就开跑」，th16 已用「中boss 存活期间章节 checkpoint 只缓存、boss 死亡 sub 出现时补显示」修掉。`ST4 MID1 → MainSub5`（= `ST4 后半 #1` 的 sub 名）在 **sub 名口径下同样会误判**。
- **对策（复用既有机制，不新增设计）**：th10 移植 th16 的「中boss 窗口」：boss 宿主里出现「中boss 死亡/逃逸 sub」（`MBossDead`/`MBossEscape`/`MBossDead_anim` 等，逐作按 `.decl` 归纳）之前，章节命中只缓存（`mPending`），窗口关闭时补显示。**注意**：th10 的 boss ECL 跑在**boss 自己的宿主**里（报告 §5.3/§5.4），而误判发生在**主线宿主**；「中boss 存活」**不必从 boss 宿主侧采集** —— 可直接读 `*(u32*)(mgr+0x10)`（thprac 既有 `bossExists`，`thprac_th10.cpp:548`；报告 **§5A.2/§5A.4**，**2026-10-18 订正**）。boss 宿主本身也**已可达**（宿主链表 `mgr+0x58` 是全宿主链，报告 §5A.1），需要时沿 `node+4` 遍历即可。
- 🟡 未真机：撞点表是**离线按指令时间推算**的，未在真机确认「中boss 存活期间主线程 ip 是否真的停在锚点上」。

### 5.2 风险 B：p1 锚点会被每次 warp 路过（🟡 低）

`ST1/ST2/ST3 前半 #1` 的锚点 = 该关**补丁位**（`0x9cb8`/`0xb764`/`0xca7c`）。warp 到 p2..pN 时主线程仍会**路过**该偏移，但此处已被换成 `ecl_time = 0` 的 `goto`（`ECLJump` 的 `ecl_time` 默认 0）⇒ 立即执行、**不在帧边界停留** ⇒ 采不到 ⇒ 不会误 latch。真机需确认「同帧内 `goto` 一定在采样前执行完」（§6）。

### 5.3 风险 C：`ECLJump`/练习跳章是否移动 ip 导致失配（✅ 不会）

- `ECLJump` 只在 `start` 处**就地覆写** `size=0x18` 的 `goto`，**不重排、不搬运**任何指令 ⇒ **其它偏移全部不变**（§2.3 判据 2）。
- `goto` 只改 `T+0`（= `at_frame`）与 `T+4`（= `dest`），不触碰 sub 表、不触碰任何旁路字段（报告 §9.2）。
- 唯一的「局部吞并」：若 `start` 处原指令 `size < 0x18`（如 st1 `0x9cb8` 原 `size = 0x10`），则 `goto` 之后的**下一条指令边界**从 `start+0x10` 变成 `start+0x18` ⇒ `start+0x10 .. start+0x18` 这 8 字节不再是指令起点。但控制流在 `start` 处即跳走 ⇒ 这些偏移**永不被观测**，**不构成本表的失配**。（本表 18 行无一行登记在被吞并区间内。）
- **分支关**：th10 **无剧情分支**（`docs/th10/th10_ecl_re_requests.md:156`「th10 无剧情分支，主线唯一」；报告 §13 同），风险不适用。
- **练习跳章**：章节滑块与 boss 滑块写同一批 `start`，后写者覆盖前者；这只影响「跳到哪一段」，不影响读取 ⇒ 无失配。
- **版本变体**：偏移是 **`.ecl` 数据**偏移，与 exe 的 RVA 无关（比地址口径更抗变体）；但**前提是各版本的 `.ecl` 一致**（Steam/汉化若改过脚本则需重算）——🟡 未核。

### 5.4 其它（🟡 实现期注意）

- **`ip == 0`**（线程已结束）⇒ `off` 会下溢成巨大值；必须先判 0 再算偏移（报告 §2.1）。
- **多线程**：B 代段入口常以 `@MainSubNN() async` 派生为**独立线程**，主线 `T+4` 可能长期停在 `main`；且 `H+4` 会被本帧最后执行过的 async 线程覆盖 ⇒ **须遍历宿主线程链 `H+0x1030`**（节点 `{+0=线程,+4=next,+8=prev}`）逐线程取 ip（报告 §4.5 / 总括 §5.1 注记）。本表 18 行里 **st1–st3 的 15 行在主线程**，**`ST4 前半 #2`（`MainSub1`）、`ST5 后半 #1/#2`（`MainSub8`）在 async 线程**。
- **res 取法**：异步线程对象只有 `0x1024` 字节、**无 `res` 槽** ⇒ 一律走全局链 `*(u32*)(*(u32*)0x477704 + 0x54)`（报告 §4.5）。
- **`slot` 号**：本章程行固定 slot 0；若日后扩到 boss 行须登记槽号（§1.3）。
