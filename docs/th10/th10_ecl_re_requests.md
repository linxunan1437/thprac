## 2. Q1 当前 sub：索引还是指令指针？（**已答：指令指针**）

**答：`[执行对象 + 4]` 是「当前指令的绝对地址」，不是 sub 索引 —— 与 th13（同代 B 代）同构。**

- 表达式：`ip = *(u32*)(T + 0x04)`（`T` = 执行对象 = 宿主 `H + 8`）；`ip == 0` ⇒ 线程已结束。
- 三处独立证据：① 主解释器 `FUN_0044E1A0` 把 `[T+4]` 当指针读 `[ins+0x04]`(opcode)/`[+0x06]`(size)/`[+0x0A]`(掩码)/`[+0x00]`(时间)；② 宿主构造 `0x40DA1F` 把 `FindSubByName(res,"main")` 的**返回值（地址）**直接写进 `T+4`；③ `goto`(opcode `0x0C` @ `0x44E40F`) 把 `ins + ins[+0x10]` 写进 `T+4`。旁证：扩展 opcode 处理器蹦床 `0x40E760` 读的是**同一个 `T+4`**。
- 「地址 → sub」的判定方式：用 `table[i].+4 + 0x10` 建**区间表**（`start_i ≤ ip < start_{i+1}`）——⚠️ 表项按**名字字典序**存放，地址不单调，必须显式排序后二分。

> 详见报告 §2（含全部写入点表）。**更正**：总括 §5.1 的「首要矛盾」在本作有明确答案 —— **th10 / th13 = 指令指针**；th15/16/17/18 = 索引，两者不可互搬。

## 3. Q2 sub 表：索引 → 名字/起始（**已答：存在，与 th13 逐字段一致**）

**答：**

```text
mgr   = *(u32*)0x477704                 // 脚本管理器（0x68 B）
res   = *(u32*)(mgr + 0x54)             // ECL 资源对象（0x1098 B，vtable 0x46D0B4）
count = *(i32*)(res + 0x08)             // sub 总数
table = *(u32*)(res + 0x8C)             // sub 表（项 8 B）
+0 = 名字 char*（指向已加载缓冲内的名字串）
+4 = sub 数据基址；首指令 = +4 + 0x10
```

- 表项 **8 字节**；名字为 **NUL 结尾 ASCII 串**（无长度前缀），位于已加载 ECL 缓冲内。
- 加载器 `FUN_00450220`@`0x450220`（`ECX`=res；SCPT 魔数 `0x54504353`、版本 1、名字区 = `buf+0x24+hdr`、`res+0xC+slot*4` = 文件缓冲数组）；按名查表 `FUN_00450470`@`0x450470`（二分，返回 `table[idx].+4 + 0x10`）。
- 游戏侧交叉印证：`0x40A6AF`（`mgr`→`res+0x54`→`res+0x8C`→`table[i].+0` 按名 spawn）、`0x40A381`（`count = res+8`）。
- `THSectionPatch` 的 `GetMemAddr(0x477704, 0x54, 0xC)` = **`res + 0xC`** ⇒ **其 `SetBaseAddr` 一级对象就是 `res`**。

> 详见报告 §3。与 th13 `res+0x8C` 表**逐字段一致**（仅管理器全局与 `mgr→res` 偏移不同：th10 是 `0x477704`/`+0x54`，th13 是 `0x4C2188`/`+0xAC`）。

## 4. Q3 函数栈（**已答：存在、可遍历**）

**答：有显式可遍历的子调用栈。**

- 栈基址 `T + 0x08`；栈指针 `SP = *(u32*)(T + 0x1008)`（字节偏移，`0` = 空栈）；**帧长 `0x08`**。
- 帧内：`+0x00` = 调用者时间（f32）；**`+0x04` = 调用者的指令地址（= 调用者当时的 `T+4`）**。
- 压帧 = `call`(opcode `0x0B` @ `0x44E35C`) → `FUN_0044DF70`；弹帧 = `ret`(opcode `0x0A` @ `0x44E20C`)。
- 遍历：`callerIp = *(u32*)(T + 0x08 + SP - 4)`，然后 `SP -= 0x08`；深度上限 ≈ `0x1000/0x08 = 512` 帧。
- ⚠️ **与 th13 的差异**：th13 帧长 `0x0C`（多一个「旧 SP」槽），th10 为 `0x08`。

> 详见报告 §4。**Q9 定案为路过式 checkpoint 后，本项不参与判定**，仅作逆向事实保留。

## 5. Q4 主线宿主捕获点（**已答**）

**答：**

- `"main"` @ `0x46D278`（全程序仅 `0x41828F`/`0x41848F` 两处引用）。
- 宿主工厂 `FUN_0040CFB0`@`0x40CFB0`（`malloc(0x2518)` → 构造 `FUN_0040D830` → **`EAX` 返回宿主 H**）。
- **捕获点（推荐）**：`call 0x40CFB0` @ `0x418299` 与 @ `0x418499` 的**下一条指令** **`0x41829E`** / **`0x41849E`**（`EAX` = H；下一条 `mov edi,[0x47770c]` 为 6B ⇒ **6B EHOOK**）。
- **静态兜底**：`H = *(u32*)(*(u32*)(mgr + 0x58))`（宿主链表头，节点 `H+0x116C`，节点 `+0` = H）。
- **零新增钩子的备选**：复用既有 `0x44fb9f` 钩子，`H = *(u32*)(Esi + 0x1014)`，用 `*(u32*)(H+0x1480) == 1296` 过滤主线后 latch。

> 详见报告 §5 / §6.4。

## 6. Q5 解释器命中点与寄存器语义（**已答**）

**答：**

- **地址**：`0x44FB9F` / RVA `0x4FB9F`，覆盖 **2 字节**（`D9 1E` = `fstp dword ptr [esi]`）。
- **指令语义**：主解释器「下一条指令时间未到」的收尾 —— `T+0 += 本帧时间增量`，然后返回 `0`。与 thprac 注释「freeze ECL sub time」一致（hook 内 `pCtx->Eip = 0x44fba1` 正是这条之后）。
- **命中寄存器**：`Esi` = 执行对象 T；`*(f32*)Esi` = 当前 ECL 时间；`*(u32*)(Esi+0x1014)` = 宿主 H。
- **所在函数**：`FUN_0044E1A0`@`0x44E1A0`（RVA `0x4E1A0`），ECL 主解释器；`>0x57` 走扩展 opcode 虚调用（宿主 vtable slot 0 = 蹦床 `0x40E760`）。
- **调用链 / 每帧次数**：`FUN_0040D750`（遍历全部宿主）→ `FUN_0040DC80`（单宿主）→ `FUN_0044FD10`（遍历该宿主线程链表）→ `FUN_0044E1A0`（**每帧每活跃线程 1 次**；单次调用内可连续执行多条指令）。
- **能否作为稳定触发点**：⚠️ **不是无条件每帧** —— 它只在「等待（时间未到）」收尾路径命中，**线程结束那一次不命中**；且**对所有脚本对象命中**（主线/敌方/boss/async），必须用 §1 的宿主角色判据过滤。
  - **推荐**：不挂 VM 钩子，在 `0x41829E`/`0x41849E` 抓一次 H，然后在 IGI 渲染（帧间稳定态）读 `T = *(u32*)(H+0x1030)`、`ip = *(u32*)(T+4)`。

> 详见报告 §6。

## 9. Q8/Q9 练习跳转补丁影响 + 段落判定口径（**已答**）

> **Q9（段落判定口径）**：**已定案为「路过式 checkpoint（latch）」**（见总括 §6 Q9）——经过白名单函数即置值、不在表内 no-op（不回退 `main`）。

- **Q8 答**：✅ `ECLJump`（`thprac_th10.cpp:1294`）只把 `goto`(`opcode 0x0C`, `ins[0x10]=dest-start`, `ins[0x14]=at_frame`) 写进运行期缓冲；`goto`(case `0x0C` @ `0x44E40F`) **只改 `T+0`(时间) 与 `T+4`(ip)**，**不影响** sub / ip 判读。
- **Q9 答**：
  - 当前 sub 取法（7 步）：H（捕获点/兜底/钩子）→ `T=*(u32*)(H+0x1030)` → `ip=*(u32*)(T+4)` → `res=*(u32*)(*(u32*)0x477704+0x54)` → `table=*(u32*)(res+0x8C)` → `ip` 经区间表得 `i` → `name=*(char**)(table+i*8)` → 白名单 latch。
  - ⚠️ **两条 🟡 未定论（详见报告 §10.4 / §10.5）**：
    1. **段落入口白名单尚未枚举**（`.ecl`/`.decl` 素材已在机，可离线枚举）；替代方案：直接用 `THStageWarp`/`THPatch` 里已有的硬编码**段落入口文件偏移**做初版白名单。
    2. **本作「入口」可能不止是 sub 名** —— 离线把 `THStageWarp` 偏移映射回 sub 后发现：**st1/st2/st3 的段落入口落在 `main` 内部**（道中是 `main` 的**内联区段**，靠 `goto` 跳过），而 **st4–st7 多为独立 `MainSubNN`**（并跑在 `async` 线程上）。故 st1–st3 可能需要 **(sub 名, ip 偏移)** 二级粒度。**该粒度决策留给阶段 E3/E4，本文件不改 CSV。**

> 详见报告 §9 / §10。
