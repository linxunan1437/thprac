## 1. 口径（先读这一节）

### 1.1 第 1 列记什么

- **格式**：`时间值/0x落点偏移` —— 十进制整数 + `/` + `0x` **大写**十六进制偏移，**无空格**。例：`3392/0xCDD4`、`68/0x472E`。正则 `^\d+/0x[0-9A-F]+$`。
- **时间值**＝该 section/portion 体内 **`thPracParam.dlg == false` 那一支**的 `ECLWarp(<time>)` 入参（A 代口径：入口列记**时间值**，不记 sub 名，见 E1 §10.4）。
- **落点偏移**＝该关时间轴上**第一条 `time >= 时间值`** 的指令的**文件偏移**（E1 §10.2 / 附录 C/D 的「落点 offset」列同义）。该偏移与运行期 `tlInstr − pCode` **精确可比**。
- **为什么偏移要进第 1 列**：th06 的时间轴上大量指令共享同一时间值、且 warp 值通常比落点时间小 0–60 帧（E1 §10.2）；**时间值单独不足以定位**，`(时间值, 落点偏移)` 才是「哪一条指令」。

### 1.4 副键是什么、为什么不进 CSV

- **副键 = boss 敌机当前 sub 索引**：`E = *(u32*)(0x4B79C8 + 0xEE598 + k*4)`（`bosses[k]`，`k=0..7`），`sub = *(u16*)(E + 0x9D8)`，再用离线表映射成 `SubN`（`SubN` 的 N **就是** sub 索引，E1 §7.2）。
- **只写进本报告，不进 CSV**：CSV 保持 **4 列**（`时间轴位置,所属游戏,所属关卡,记录名`），不造伪副键 —— 同 `docs/th08/th08_checkpoint_entry_report.md` §8 的裁决口径。
- 为什么需要副键：boss 段的 `(时间值, 落点偏移)` **大量重复**（§3.1：12 组 / 67 行），一级键只能定「进了哪个 boss 容器」，定不了「第几个相位」。

### 1.5 ECL 侧交叉验证方法（本轮新增，素材 2026-10-21 备齐）

**（1）th06 `.ecl` 头（本机 7/7 实读，与 th07 / th08 均不同，勿照搬）**

```text
+0x00  i16 subCount
+0x02  i16 （恒 0）
+0x04  u32 timelineOffset      // 加载器 0x407340 就地改成 pCode+offset
+0x08  u32 （恒 0）            // ECLSRC+8 = pCode + *(u32*)(pCode+4)
+0x0C  u32 （恒 0）
+0x10  u32 subOffset[subCount] // 就地改成绝对地址；sub 脚本区 [0x10+4*subCount, timelineOffset)
pCode+timelineOffset  时间轴指令区（连续到文件尾前 4 字节终止标记 FF FF 04 00）
```

- **时间轴指令头 8 B**：`{i16 time@+0, i16 arg0@+2, i16 op@+4, i16 size@+6}`（参数自 `+8` 起，`size` 含 8 B 头）。
- **sub 指令头 12 B**：`{i32 time@+0, i16 op@+4, i16 size@+6, u8@+8, u8 diffMask@+9, u8@+0xA, u8@+0xB}`（参数自 `+0xC` 起）。`diffMask` 的位 `1<<difficulty` 置位 ⇒ **该难度跳过此条**（`0x4074F6`）。
- 实测统计（与 E1 附录 A.2 逐项相同）：

**但「补丁落在哪个 sub」≠「section 生效时停在哪个 sub」**：补丁是**改写前序相位让它跳过**的（例如 `ST1 BOSS3` 同时改 `Sub11` 与 `Sub16`，前者是「把相位 1 关掉」，后者才是它自己的相位）。所以还需要（b）。

#### （b）boss 控制器脚本的相位链（`0x6D` / `0x6E` / `0x6C` / `0x73` / `0x74`）

**指令跳表**（`0x40A9A4`，索引 `opcode−1`，本机 `capstone` 复核）：

| op | handler（VA/RVA） | 语义（反汇编判据） |
| --- | --- | --- |
| `0x6C`(108) | `0x409510`/`0x9510` | **死亡回调 sub**：`mov eax,[ins+0xC]; mov [E+0xC44],eax` ⇒ `E+0xC44 = arg0` |
| `0x6D`(109) | `0x409524`/`0x9524` | **登记中断**：`mov ecx,[ins+0]; mov edx,[ins+4]; mov [E+edx*4+0xC48],ecx` ⇒ `interrupts[arg1] = arg0` |
| `0x6E`(110) | `0x40953E`/`0x953E` | **自触发中断**：`mov [E+0xC68],arg0` 后**直落** `0x40954D`（中断入口） |
| `0x6F`(111) | `0x4095FC`/`0x95FC` | `mov [E+0xCE8],arg0` ⇒ **设 HP** |
| `0x73`(115) | `0x409A07`/`0x9A07` | `mov [E+0xEB0],arg0` ⇒ **设超时**（`th06_lock_timer2` 用的就是它） |
| `0x74`(116) | `0x409A4F`/`0x9A4F` | `mov [E+0xEB4],arg0` ⇒ **设「超时后切到哪个 sub」** |

**外部触发（时间轴 op `0xA`）**：跳表 `0x411D63 + 10*4` = **`0x411C3B`**；实测 `0x411C53: mov ecx,[edx+8]`（＝`instr->arg0`）→ `0x411C5C: mov ecx,[mgr+ecx*4+0xEE598]`（＝`bosses[arg0]`）→ `0x411C63: mov edx,[eax+0xC]`（＝`instr->arg1`）→ `0x411C66: mov [ecx+0xC68],edx` ⇒ **`bosses[arg0]->runInterrupt = arg1`**（与 E1 §12 附录 B 一致）。

**中断进入**：VM 每帧入口 `0x4074C0: cmp dword [E+0xC68],0 / jl 0x4074CE / jmp 0x40954D`；`0x40957B-0x40959F` 先按 `call` 的同一格式压栈（`rep movsd 0x13` = `0x4C` B），`0x4095A1-0x4095AD` 取 `(u16)E[0xC48 + runInterrupt*4]`，`0x4095BF-0x4095C4` `call 0x407440`（`SetSub`）⇒ **`E+0x9D8 = interrupts[runInterrupt]`**。

**相位内交接（超时 → 换 sub）**：`0x411F40`（敌机「待处理动作」runner，`th06_lock_timer4` 所在函数）实测：

```asm
00411F9C  cmp  edx, [ecx+0xEB0]        ; E+0xCF8（本地帧计数） >= E+0xEB0（超时值）?
00411FA2  setge al / test eax,eax / je 0x4121A9
00411FD8  mov  cx, word [E+0xEB4]      ; ★ 超时后要切到的 sub
00411FEC  push &E+0x990                ;   &ctx
00411FF2  call 0x407440                ; ★ SetSub ⇒ E+0x9D8 = E+0xEB4
00411FFA  mov  dword [E+0xEB0], -1     ;   清超时
0041200A  mov  eax, [E+0xC44]          ; ★ 下一次默认切到「死亡回调 sub」
00412010  mov  [E+0xEB4], eax
```

⇒ **一个「相位 sub」内部还会再切成「spell / 弹幕子 sub」**：`0x73` 设超时、`0x74` 设目标，超时到点就 `SetSub`。这就是「同一落点、同一相位脚本，却有两个 section（非符 / 符卡）」的物理原因。

**由此得到的副键判定规则（机械、可复算）**：

1. **取该 section 所有补丁偏移（`pair`/`SetTime`/`SetHealth`/`Stall`/`Jump`）落在 sub 区间内的最深 sub `D`**（「最深」= 补丁要跳过的前序相位之后的那个）。
2. 若该 section 在 `D` 上下了 **`ECLSetTime`**（把 `D` 内的 `0x73` 超时改写成 0 ⇒ **立刻交接**），则副键 = **`D` 的 `0x74` 目标**（`0x74` 在 force 点之前的最后一条；`E+0xEB4` 逐条写入、后写覆盖）。
3. 否则副键 = `D`。
4. 若该 section **没有任何补丁**（如 `ST2 BOSS1` / `ST4 BOSS1` / `ST7 MID1`），副键 = **落点首 spawn 的控制器 sub 的 `irq[0]` 目标**（= 第一相位）；若该 spawn sub **本身没有 `0x6D`**（它自己就是中boss 相位脚本），则副键 = **该 sub 自身**（`ST2/ST3/ST4 MID1` 属此档）。
5. `ECLStall`（冻结）与 `ECLJump`（改控制流）**不切 sub**，不算交接触发（`ST4 BOSS6/7`、`ST6 BOSS9` 就是这种）。

> 规则的每一档都在 70 行上**逐行落表**（§3.4），并与 `th_sections_cbt`（`thprac_locale_def.cpp:7669` 起：非符/符卡两条列表）**逐关对得上**：非符 section ↔ 相位 sub，符卡 section ↔ 该相位的 `0x74` 目标 sub。

#### （c）运行期读取链与瞬态消歧

```cpp
constexpr uint32_t ENEMY_MANAGER = 0x4B79C8;   // 静态，无需捕获（E1 §5）
uint32_t pCode   = *(uint32_t*)0x487E50;                    // 当前关 ECL 缓冲
uint32_t tlInstr = *(uint32_t*)(ENEMY_MANAGER + 0xEE5DC);   // 下一条待执行的时间轴指令
int32_t  tlTime  = *(int32_t*)(ENEMY_MANAGER + 0xEE5E8);    // = *(int32_t*)0x5A5FB0
uint32_t tlOff   = tlInstr - pCode;                         // ★ 一级键

// 二级键：boss 敌机（k = 0..7，空槽为 0）
uint32_t E = *(uint32_t*)(ENEMY_MANAGER + 0xEE598 + k * 4);
uint16_t sub   = *(uint16_t*)(E + 0x9D8);   // ★ 当前 sub 索引（→ SubN）
uint32_t ip    = *(uint32_t*)(E + 0x990);   // 当前指令（绝对地址）
int32_t  rirq  = *(int32_t*)(E + 0xC68);    // runInterrupt：-1 = 无；>=0 ⇒ 下一帧进中断
int32_t  irqSub= *(int32_t*)(E + 0xC48 + rirq*4);  // 该中断要跑的 sub id（rirq ∈ 0..7）
int32_t  death = *(int32_t*)(E + 0xC44);    // 死亡回调 sub（相位链的下一级）
```

**瞬态（「阶段已登记但尚未起跑」）怎么判** —— 三种状态必须分开：

| 状态 | 判据 | 该报哪一段 |
| --- | --- | --- |
| 已登记、**尚未**触发 | `E+0xC68 == -1` 且 `E+0xC48[0] != -1` 且 `E+0x9D8` 仍是**控制器** sub（有 `0x6D`、无 `0x6F` HP） | **不要**报目标相位；保持上一值（no-op）。th06 里这个窗口只有 **2–3 帧**（`ST1`：boss spawn t=5279、`0xA` @t=5281；`ST6`：t=3169 / `0xA` @3171、3173） |
| 已触发、**正在**跑 | `E+0xC68 == -1` 且 `E+0x9D8` ∈ 相位 sub 集合 | 报 `E+0x9D8` 对应 section |
| 已超时、**刚要**换 sub | `E+0xC68 == -1` 且 `E+0xEB0 >= 0` 且 `E+0xCF8 >= E+0xEB0`（本帧内会被 runner 改写） | 用 `E+0xEB4`（= 即将切到的 sub）预判，或等下一帧再看（推荐后者，简单且不会误判） |

> `ST6` 是唯一「两级中断」的关：控制器 `Sub15`（`0x6D`@`0x1486` → `irq[0]=16`）→ `Sub16`（`0x6D`@`0x14D6` → `irq[0]=17`）→ `Sub17`（第一相位）。时间轴上因此有**两条** op `0xA`：`0x784E`(t=3171) 与 `0x7866`(t=3173)，相隔 2 帧。读 `E+0x9D8` 在这两帧里会看到 `16 → 17`，属正常瞬态。

## 7. 监控两级判定流程（E5 实现口径，🟡 未真机）

> 本节回答实现层必答题：**第 1 列的 `(时间值, 落点偏移)` 在 boss 段大量重复，监控凭什么分辨「现在打到第几个相位」？**
> 结论：**单靠第 1 列做不到，必须两级判定** —— 一级＝时间轴落点（进哪个 boss 容器），二级＝boss 敌机的 `E+0x9D8`（第几相位）。地址全部沿用 `docs/th06/th06_ecl_re_report.md`；结论仍为 **🟡 静态定案、未真机**。

### 7.1 两级模型

```text
每帧（IGI 渲染、帧间稳定态）：
  ① 一级：tlOff = tlInstr − pCode；与白名单「落点偏移」**精确相等**匹配
          → 候选 = 该落点的 1..18 个记录名（§3.1）
  ② 二级：读 bosses[k] 的 E+0x9D8（→ SubN）+ E+0xC68/E+0xC48（瞬态）
          → 在候选里按「副键 SubN」选出唯一一条
  ③ 合并：候选唯一 ⇒ 直接置；候选多个且副键无命中 ⇒ no-op（保持上一值，不回退 main）
```

- **为什么一级用「偏移精确相等」而不是「时间取最大 ≤ 」**：同一帧内时间轴上会有多条指令共享同一 `time`，且 warp 值常比落点时间小 0–60 帧（E1 §10.2）；`tlInstr` 是**唯一确定的一条指令**，精确相等天然满足 latch 语义。
- **为什么二级不读「补丁写进去的字节」**：正常游玩时 thprac **根本没打补丁**，读到的是原始值 ⇒ 只能读**运行期 sub 索引**（§3.2c）。
- **章节行永远不需要二级**：39 个章节落点**两两不同**、且**不与任何 boss 行共享落点**（12 个多行组全部落在 boss 轴）⇒ 章节行一级键命中即可定段；`SubN` 列对章节行只是「落点首 spawn」的参考值。

### 7.2 伪代码（可直接翻成 C++）

```cpp
struct Row { uint32_t off; const char* name; int16_t subKey; };  // subKey < 0 = 该行无副键（章节）
// 由 §2 表机器生成：109 行，按 (stage, off) 分组

constexpr uint32_t MGR = 0x4B79C8, ECL = 0x487E50;
static const char* mSection = "main";
static int mLastSubKey = -1;

void Tick() {
    uint32_t pCode = *(uint32_t*)ECL;
    uint32_t tl    = *(uint32_t*)(MGR + 0xEE5DC);
    if (!pCode || !tl) { mSection = "main"; mLastSubKey = -1; return; }   // 未进关 / 管理器刚清零
    uint32_t off = tl - pCode;
    if (off >= 0x10000) { mSection = "main"; return; }                    // 越界保护（ECL ≤ 60796 B）

    // ① 一级：落点精确相等
    auto* grp = FindGroup(off);              // 该落点的 1..18 行；无则 nullptr
    if (!grp) return;                        // 不在白名单 ⇒ no-op（保持上一值）

    // ② 二级：boss 当前 sub
    int16_t cur = -1;
    for (int k = 0; k < 8; ++k) {
        uint32_t E = *(uint32_t*)(MGR + 0xEE598 + k*4);
        if (!E) continue;
        int16_t s = *(int16_t*)(E + 0x9D8);
        if (s < 0 || s >= 0x4000) continue;                       // 非法
        if (IsKeyOf(grp, s)) { cur = s; break; }                  // 只接受「本组候选的副键」
        // 瞬态：runInterrupt >= 0 ⇒ 下一帧才进中断，本帧先不判
    }

    if (grp->n == 1) { mSection = grp->rows[0].name; return; }     // 落点唯一 ⇒ 不需副键
    if (cur >= 0)   { mSection = NameOf(grp, cur); mLastSubKey = cur; return; }
    // 副键无命中 ⇒ 保持上一值（latch），不回退 main
}

// 复位点：进关 / *_game_start（E1 §9 第 4 条：ECLWarp 不回退指针）
void Reset() { mSection = "main"; mLastSubKey = -1; }
```

### 7.3 三个已知坑（🟡 全部未真机）

**（1）`ECLWarp` 后同帧连跳 ⇒ 帧边界 `tlInstr` 可能已越过落点**

`0x4115D3` 的循环在同一帧内会把 `tlInstr` 逐条 `+= size`（`0x411D15`）直到第一条 `time >= t`；若落点那条指令**不阻塞帧**（`time` ≤ 当前时间），同帧就会继续前进 ⇒ 采样看到的 `tlOff` **已经是落点之后**。这是 th13 真机实测过的同型问题（`docs/th13/th13_monitor_impl_report.md` §8：`ST5 后半 #4` 的落点 `0x54d0` 不阻塞帧、帧边界永远不是它）。
- th13 的做法是把「等式」改成**区间/位置比较**（`mOffsetRows` 按 `off` 降序 + `delta >= off` 取「包含 ip 的最内层段」）。
- **本报告只引用、不照搬**：th06 的落点大多是**生成类 op 0/2/4/8/9**（会生成敌机、`time` 通常等于 warp+0..60），是否阻塞帧**未真机验证**。若真机发现某些落点被跑穿，再决定是否改成 `tlOff >= off`（区间式）——**那会改变 latch 语义（可能跨段落误命中），必须真机数据支撑后再改**，不在本轮定案。

**（2）指针不回退 ⇒ 重置点必须靠进关 / `*_game_start`**

`ECLWarp` 只写 `mgr+0xEE5E8`（时间），**不动 `tlInstr`**；同一局内往回 warp 时 `current < instr->time` 只会「等待」，指针**不会回退**（E1 §9 第 4 条）。⇒
- 必须把「进关 / 重开」当**唯一复位点**（th06 进关会 `0x410E30` 全量清零管理器 + `0x407340` 重载 ECL，E1 §5.1）；
- 反向判据：`pCode` 变化（换关/重载）或 `tlInstr` 落回 `pCode + *(u32*)(pCode+4)` 附近 ⇒ 复位。

**（3）中boss 窗口（st1/st2/st4/st5 缺 `boss_wait`）⇒ 章节 checkpoint 可能被跑穿**

thprac 的 `TH_TIMELOCK` 注释写明这几关的中boss **缺 `boss_wait`**（时间轴上没有「等 boss 死」的 op `0xC`），所以正常游玩时中boss 战期间**时钟不冻结**，`tlInstr` 会一路掠过后续章节入口（E1 §10.2 caveat 1；本报告实测：这 4 关的时间轴 op `0xC` 数为 `1/1/1/1`，而 st3/st6/st7 为 `2/2/2` —— 中boss 段确实没有独立的 `0xC`）。
- **对策（移植，不新设计）**：`docs/th16/th16_monitor_impl_report.md` §5.7 的「中boss 存活期间**章节 checkpoint 只缓存（`mPending`）、死亡 sub 出现时补显示」。
- th06 侧判据：`bossPresent = *(u8*)0x69BC50`（`ZunGui+0x20`）＋ `bosses[k]` 的 `E+0x9D8` 是否落在**中boss 相位 sub 集合**（每关 §3.3 的中boss 链）；中boss 的「死亡 sub」需真机归纳（本报告不猜）。
- 实测（本轮离线统计，时间轴 op `0xC` 的 `(偏移, time)`）：ST1 `(0x5FD6,5282)`、ST2 `(0x68E4,5987)`、ST4 `(0xED60,10698)`、ST5 `(0x769C,7707)` **各只有 1 条**（＝只等关底 boss）；ST3 `(0x6C4A,3805)`+`(0x8112,5917)`、ST6 `(0x7812,2567)`+`(0x7876,3174)`、ST7 `(0xD302,4743)`+`(0xE9D6,8597)` **各有 2 条**（＝中boss 与关底各一条）⇒ **「st1/st2/st4/st5 缺中boss 的 `boss_wait`」由字节直接证实**。
- 影响面：`ST1 MID1/MID2`（warp 2008）与 `ST1 后半 #1`（warp 2348）相差 **340 帧**；`ST4 MID1`（4132）与 `ST4 后半 #1`（4872）相差 **740 帧**；`ST5 MID1/MID2`（3372）与 `ST5 后半 #1`（3814）相差 **442 帧** ⇒ **窗口足够长，误命中概率不低**，建议实现时**先只缓存**。
