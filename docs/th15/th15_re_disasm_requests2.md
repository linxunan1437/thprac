## 0. 背景与现状

第一轮报告 §1.1 认为 `[boss+0x4070]` 是"当前攻击序号"，实测（练习 + 普通流程）**恒为 0，全面不可用**：opcode 0x200（case 0x37）只会在 boss 进场/退场时写一次该字段，boss 战内换攻击走 opcode 0x202（case 0x39 / SetNextPattern），**不更新 `+0x4070`**。

我方按报告 §2.4 挂 `0x42C7D6`（`call 0x0042ff10` 调用点）读取 FUN_0042ff10 的栈参数，实测 **栈参数内容与报告 §2.4 "param_1=当前阶段、param_2=下一阶段" 的描述不符**，详见 §1 诊断数据。需要反编译组给出 FUN_0042ff10 的真实签名与 case 0x39 全链路，定位可挂接的"下一攻击序号"来源。

## 1. 诊断数据（0x42C7D6 钩，EHOOK 5 字节）

hook 命中时机：`call 0x0042ff10` 尚未执行，ESP 指向返回地址。实测转储（节选，完整见 `th15_missbomb_debug.txt`）：

```
setnext: edi=114431fc esi=00000898 eax=00000000 ecx=??? edx=??? ebx=??? ebp=???
  args: +4=00000960 +8=10cabd9c +c=e48c0bf1 +10=??? +14=??? +18=??? +1c=??? +20=??? +24=???
```

关键事实：

| 项 | 实测值 | 说明 |
| --- | --- | --- |
| `[esp+4]` | `2400 / 2100 / 2280 / 1500 / 3000` | 跨 boss 重复、顺序非单调，**不是阶段序号**；疑似某阶段 HP |
| `[esp+8]` | 约 `0x10cabd9c` 等堆地址 | **= 本次 case514 命中时 `ESI + 0x20`**（例：case514 esi=0x10cabd7c → [esp+8]=0x10cabd9c）。即报告 §2.4 所述 "第 4 参 = [ESI+0x20] 对象子结构指针" |
| `[esp+0xC]` | `0xe48c0bf1`（-460462095） | 全日志恒定，非阶段 |
| `EAX` | `0` 或 `1` | 非阶段 |
| `ESI`（0x42C7D6 处） | 正常分支为 `0`；BossDead 分支为 `0x898/0x960/0x9c4/0x6a4/0x76c/0x578` 等 | 这些值量级同 `[esp+4]`，疑似血量类 |
| `[edi+0x4070]` | 始终 `0` | 已确认不可用 |
| `[edi+0x3F80]` | 换攻击时变化（99400→93800→94500…），但**攻击进行中继续变**（如 99400 → bomb 时 1239） | 易变，疑似 HP 相关，不可作阶段 |
| case512（0x42B938）`EAX` | 进场 `0`、退场 `-1` | 只覆盖第一攻击，可作兜底 |

> 结论：报告 §2.4 对 FUN_0042ff10 参数编号/栈偏移的描述与实测不符（实测 `[esp+8]` 即"第 4 参"，说明真实参数多于 4 个或在栈上有更早的参数）。**真实"下一攻击序号"应在 `[esp+0x10]` 及以上栈位或某寄存器中，本次日志未覆盖**。
