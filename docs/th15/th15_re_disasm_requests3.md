## 0. 背景与现状

第二轮报告 §3.2 推荐以 `[*(g_boss_ptr+0x44B8)+0x528B]` 作为"当前攻击名"主记录源。开发组落地后实测：

1. **该源在 miss/bomb 时读到的为空串**（boss 战记录全部 `-`）。
2. 扩展候选源实测（HUD 调试，见 §1）：**`@5314`（`scr + 0x88 + 0x528C`）可稳定读到"下一攻击"的名字**；其余候选（`@528B/@528C/@5313`、boss 对象 `@4080`）连"下一阶段"都读不到（空串）。

需要反编译组确认名字串写入机制，并给出 miss/bomb 时点可稳定读到**当前攻击名**的精确位置。

## 1. 实测数据（HUD 调试显示，各候选源值）

练习模式 ST1 boss 按阶段 bomb/miss，InGameInfo 显示（`g_boss_ptr` = 缓存的 EDI，`scr` = `[g_boss_ptr+0x44B8]`）：

```
MB last: b(BossCard1)                    ← 实际记录的值（当前版本优先 @4080，读到下一阶段）
DBG boss=10e07644 flg=1 scr=10e06438
@528B=""   @5313=""                      ← 空（param_1=0 的两个偏移，均无名字）
@528C=""   @5314="BossCard1"             ← @5314 稳定读到"下一攻击"名；@528C 空
@4080=""                                 ← 本版实测为空（与上一版 dump 显示有值不一致，可能时机/对象差异）
```

> **关键实测结论（2026-08-19 追加）**：
> - **`@5314`（`scr + 0x88 + 0x528C`）是唯一稳定有值的源，内容是"下一攻击"的名字**（练习序列 非符1→符卡1→非符2→符卡2 时各阶段读到 符卡1/Boss2/符卡2/BossDead，恰为下一阶段）。
> - 其余候选（`@528B/@528C/@5313`、`@4080`）本轮实测均空（空串），**连"下一阶段"都读不到**。
> - 即：名字串真实写偏移为 `script + param_1*0x88 + 0x528C`，且测试关卡的 `param_1`（ECL 参数[0]）= **1**；`+0x528B` 与 `+0x528C`（param_1=0 槽）为空。

> 各源读取表达式：
> - `@528B = (char*)(scr + 0x528B)`；`@528C = (char*)(scr + 0x528C)`；
> - `@5313 = (char*)(scr + 0x88 + 0x528B)`；`@5314 = (char*)(scr + 0x88 + 0x528C)`（`param_1`=ECL 参数[0]，0 或 1，偏移 `param_1*0x88`）；
> - `@4080 = (char*)(g_boss_ptr + 0x4080)`（boss 对象直接偏移）。

已知事实：
- `flg = [g_boss_ptr+0x4060] & 0x800000` 在 boss 战中为 1（boss 战判定可靠）。
- `[g_boss_ptr+0x44B8]`（ECL 脚本资源指针）在 boss 战中非空（scr 有值）。
- 上一版仅读 `@528B` 时记录全 `-`；当前版优先读 `@4080` 能记录但语义为"下一攻击"；本轮实测 `@4080` 为空、`@5314` 有"下一攻击"名。
- `@5314` 有值 ⇒ 报告2 §1.1 的 off-by-one 判断成立（字符串起点 = `+0x528C` 而非 `+0x528B`），且该槽对应 `param_1=1`。

## 2. 反编译需求

### 问题 1：boss 对象 `+0x4080` 字段的写入点与语义

- 反汇编 `[g_boss_ptr+0x4080]` 的全部写入点（写指令地址 + 调用链）。
- 它是什么缓冲？（"下一攻击预告 / 次弹幕显示名 / 当前攻击名"？）
- 写入时机：每攻击**开始**还是**结束**时写？写的是"当前攻击"还是"下一攻击"的名字？此缓冲在攻击进行中是否变化？
- 若能给出该字段的写入源（`FUN_0042ff10` 的 `param_3`？`[ESI+0x20]` 名字子缓冲？其它），一并说明。
- 注：上一版诊断 dump 中 `@4080` 曾显示下一攻击名（BossCard1/Boss2/BossCard2/BossDead），本轮实测为空——请说明其写/读的稳定性差异（是否仅在特定分支写入、是否被后续清空）。

### 问题 2：名字串写入机制 与 miss/bomb 时点"当前攻击名"的稳定读取位置

- 第二轮报告 §3.2 推荐 `[*(g_boss_ptr+0x44B8)+0x528B]`，实测为空。**off-by-one 已基本确认**：实测 `@5314`（`script+0x88+0x528C`，即 `param_1=1` 且起点 `+0x528C`）稳定读到"下一攻击"名，其余候选空。请从**逐字节指令**确认：
  - 字符串起始偏移确为 `+0x528C`（第二份副本 `+0x52CC`）？
  - 测试关卡各攻击的 `param_1`（ECL 参数[0]）恒为 1？`param_1=0` 的槽（`+0x528C`）为何为空？
- **为什么这个槽存的是"下一攻击"而非"当前攻击"**：`FUN_0042ff10` 在 `0x202` 换攻击时写入的名字，按理在进入该攻击后即"当前"。请确认名字串的**写入时机**（每攻击开始即预置下一攻击？还是换攻击瞬间写？）及**谁负责推进**（ECL 脚本 `ins_514` 的调用时序）。
- 给出 **miss/bomb 时（boss 战进行中，`flg` 为 1）可稳定读到"当前攻击名"** 的最终方案：
  - 若"当前攻击名"确无内存直接来源：确认开发组的候选做法是否可行 —— 在换攻击钩（`0x42C7D6`/`0x42C785`）处缓存"写前旧值"（= 即将进入的攻击名，即新攻击进行中的"当前名"），miss/bomb 时读缓存。
  - 或按报告2 §3.3 自维护计数（给出该点名字/HP 所在寄存器/栈位）。

## 4. 附：当前实现（开发组侧，`thprac_th15.cpp` `TH15MissBombRecorder::GetBossStageName`）

```cpp
static std::string GetBossStageName()
{
    if (!g_boss_ptr) return {};
    if (!(*(uint32_t*)(g_boss_ptr + 0x4060) & 0x800000)) return {};
    std::string n = ReadName(g_boss_ptr + 0x4080);   // 实测：本轮为空（上版 dump 曾显示"下一攻击"名）
    if (!n.empty()) return n;
    int script = *(int*)(g_boss_ptr + 0x44B8);
    if (script) {
        n = ReadName(script + 0x528B);               // 报告2 §3.2 推荐，实测空
        if (!n.empty()) return n;
        n = ReadName(script + 0x88 + 0x528B);        // 实测空
        if (!n.empty()) return n;
        n = ReadName(script + 0x88 + 0x528C);        // @5314：实测稳定读到"下一攻击"名（暂未优先）
        if (!n.empty()) return n;
    }
    return {};
}
```
