# TH15 miss/bomb 记录：非 boss 阶段判定所需的 ECL 时间信息（第五轮反编译请求）

> 状态：**待反编译组回复**。前四轮：`th15_re_disasm_requests.md` + `th15_re_disasm_report.md`、`requests2 + report2`、`requests3 + report3`、`requests4 + report4`。
> 范围声明：**仅 ST1~ST6（ST7/EX 不做，无需反馈 EX 相关内容）**；**仅 thprac 练习模式（thp）**，不涉及正常游玩。
> 目标：miss/bomb 时给出"当前处于非 boss 阶段的哪一段"的**唯一标识**（标识命名不重要，能区分即可）。

## 0. 背景与现状

### 0.1 功能目标

thp 模式下 miss/bomb 时记录当前游戏阶段，一局一行落盘 `th15_missbomb.txt`。boss 战阶段名已由前三轮方案解决（换攻击钩缓存名字串）。当前非 boss（道中）时段一律记 `-`，本次补上非 boss 阶段的记录。

### 0.2 方案（开发组已定）

**不使用任何章节号/章节类指令字段**（该方案开发组已排除）。改读 **ECL 自身的执行时间**：

1. 确定本局 ECL 开始执行时间 `t0`（ECL 内部有一个时钟，用于按时间驱动事件）；
2. miss/bomb 时读取当前 ECL 时间 `t`；
3. 用 `t - t0` 对照 ECL 脚本内的时间（阶段边界复用 ECL 跳转的章节划分）判定当前非 boss 阶段。

阶段边界时间表由开发组按 `docs/th15/ECL/` 的脚本与 ECL 跳转划分自行整理；本次反编译只需解决 **"运行期如何取到 ECL 时间与基准"**。

### 0.3 缺口

thprac 现有 TH15 ECL 相关钩子（`0x42B938`/`0x42C738`/`0x42C7D6`/`0x42C785` 等）都挂在 boss 指令/攻击名写入上，命中时不携带时间信息；全仓库没有任何读取 ECL 执行时间的代码。TH15 的以下信息均未知：

- ECL 执行对象（执行上下文）的时间字段偏移与类型；
- 每帧推进该时间的指令地址；
- 如何定位"关卡主线脚本"的执行对象；
- thp 补丁跳转（`ECLJump`）对时间字段的影响。

### 0.4 开发组已探明信息（无需重复劳动）

**TH15 已知：**

| 项 | 内容 |
| --- | --- |
| ECL 解释器 | `FUN_004291e0`（`0x4291E0~0x42DBCB`）；case 512/514 = opcode `0x200`/`0x202` |
| ECL 管理器 | `0x4E9A80`：`+0x180` 链表、`+0x18C` 活跃脚本计数、`+0x48+序号*4` 阶段数据槽 |
| thp 补丁写入区 | `0x4E9A80 → +0x17C → +0xC`（`ECLHelper` 基址） |
| 现有钩子地址 | miss `0x456398`、bomb `0x41497A`、进关 `0x43E6EE`（`th15_game_start`）、thp 补丁执行 `0x43c68C` |
| thp 跳转补丁格式 | 见 §1 问题 3 |

**他作参照（当年做雷锁时挖出的"零件"，地址/偏移不保证 TH15 一致，仅供定位思路）：**

- **TH14**（`thprac_th14.cpp` 的 F5 钩子，`0x483c4f`，覆盖 4B）：
  - 命中时 `pCtx->Edi` = ECL 执行对象，`[Edi+4]` = 当前指令指针；
  - 跳过该指令 = 该对象的时间不再前进（"freeze ECL sub time"）；
  - sub 表 = `[ENEMY_MANAGER_PTR(0x4db544)+0xcc]+0x8c`，每项 8B，`+4` = 该 sub 起始指令地址；用"当前指令指针落在 `[start,end)`"判断归属。
- **TH11**（`thprac_th11.cpp` 的 F5 钩子，`0x45d2a3`，覆盖 2B）：
  - 命中时 `pCtx->Edi` = 主线脚本执行对象；
  - **`*(float*)pCtx->Edi` 即当前时间值**（已实际读取并参与比较）；
  - 主线判定 = `[Edi+0x1014]+0x103c+0x1580`（enemy flags）== `20512`。

### 0.5 开发组已有实现

- 记录模块：`thprac/src/thprac/thprac_th15_missbomb.cpp` / `.h`（`TH15MissBombRecorder`）。
- boss 阶段名：换攻击钩（`0x42C7D6`/`0x42C785`）缓存，miss/bomb 回调内读取。
- 现状：非 boss 记 `-`；落盘行格式 `ST<关> m(<阶段>)/b(<阶段>)`。

## 1. 反编译需求

### 问题 1：ECL 执行对象的时间字段与每帧推进点

- TH15 中，ECL 执行对象（解释器当前操作/维护的那个对象）的时间值存在哪个偏移？类型是 int 还是 float？单位是帧吗？是否可能为负？
- **每帧推进该时间的指令地址**（即 TH14 `0x483c4f` / TH11 `0x45d2a3` 在 TH15 的对应物）；命中时哪个寄存器（`Edi`？）/栈位指向该对象；在该点读到的值是推进前还是推进后？
- 推进是"每个活跃 ECL 对象每帧各一次"还是别的组织方式？给出所在函数与调用链（谁驱动）。
- 期望结论：`读时间表达式 = 对象指针 + 偏移`，以及推进点地址。

### 问题 2：如何定位"关卡主线脚本"的执行对象

- 运行期给一个**无歧义定位主线脚本对象**的表达式或遍历规则（全局指针链优先，需要挂钩也行）。候选线索：`0x4E9A80` 管理器（`+0x180` 链表、`+0x18C` 计数等）。
- 主线脚本内的同步子调用（如 `@MainFront()`、`@MainLatter()`）是**同一对象继续计时**，还是新建/切换对象？"主线时间"是否为单一连续时钟？（这决定 `t0` 与时间差的口径。）
- 确认：TH14 的"sub 表 + 指令指针区间"与 TH11 的"enemy flags == 20512"两种做法，哪种与 TH15 结构接近？

### 问题 3：thp 补丁跳转（`ECLJump`）对时间的影响

thp 模式用如下补丁把 ECL 指针跳到段落入口（`thprac_th15.cpp`，`ECLJump`）：

```cpp
ecl << ecl_time << 0x0018000C << 0x02ff0000 << 0x00000000 << dest - start << at_frame;
```

- 该跳转指令生效时，对执行对象的**时间字段**做什么？保持原值 / 重置为某个参数 / 直接改写？`at_frame` 与 `ecl_time` 各自的语义是什么？
- 游戏自身的时间跳转/时间标签（脚本里 `goto ... @ T`、`+N:` 时间标签）是如何与时间字段交互的（比较、等待、还是改写）？
- 期望产出：thp 补丁后"本段 ECL 起点时间 `t0`"的计算规则（例如 `t0 = 跳转时的对象时间 + at_frame` 之类）。

### 问题 4：时间推进的冻结/暂停

- 主线 ECL 时间在 **boss 战、对话、Esc 暂停、GameOver/Continue** 等情况下是否停止推进？由哪段代码控制？
- 若存在冻结/跳跃，请说明读取到的时间是否连续；如有必要，是否另有"累计帧数/偏移"字段可配套使用。

### 问题 5：推荐挂钩点与读取方案

- **捕获 `t0`**：给出主线 ECL 对象创建/重置/进关时的时间捕获点（现有 `0x43E6EE`（进关）、`0x43c68C`（thp 补丁执行）是否可用，或更合适的地址）。
- **运行期读取**：给出最优方案——优先"全局指针 + 偏移"的无钩读取；否则挂"每帧推进时间"的轻量钩子（每帧一次级别）缓存时间值。
- 给出命中时寄存器/内存语义与建议 EHOOK 覆盖长度。
