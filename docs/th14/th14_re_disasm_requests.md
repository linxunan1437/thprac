## 0. 本轮需要的是"地址 + 判据"，不是 hook

与以往的需求不同：**本次不需要在游戏里挂钩子，只需要给出可以跨进程读取的静态地址与判定条件。**

因此对交付物的硬性要求：

1. 必须是**进程内固定地址**（`.data` / `.bss` 段里的全局量，或"全局指针 + 固定偏移链"），不能是栈上/寄存器里的临时值。因为读取方在**另一个进程**里，只能 `ReadProcessMemory(base + RVA)`。
2. 必须给出**取值语义**：等于什么表示"暂停中"/"正在回放"，以及**不在该状态时的取值**。
3. 必须能在**任意时刻**安全读取（读失败会被当作"不计时"，不会崩，但会造成漏计）。若某地址只在特定阶段有效，请特别标注。
4. 若需要**两级指针**（全局指针 → 偏移 → 字段），请给出完整链路与每一级的存在性条件（指针为 0 时怎么办）。

## 1. "未暂停"标志（最关键）

### 目标
需要判断"**游戏自身的暂停菜单是否处于打开状态**"。

注意区分：这**不是** thprac 自己的 `THPauseMenu`（那是注入后的 thprac 界面），而是游戏原生的暂停菜单——玩家按 Esc / 暂停键打开的那个。

### 需要确认的问题
1. 游戏把"暂停菜单是否打开"存在哪个地址？
   - 是全局字节/整数，还是某个全局指针指向的对象里的字段？给出地址或**指针链**。
2. 取值语义：什么值表示"暂停菜单已打开"？"未打开"时是什么值？
3. 在**非游玩状态**（标题画面、菜单、选人、结算）下这个地址是什么值？我们需要确保这些状态下判据也不会误判为"正在游玩"。
4. 该地址在**整个进程生命周期内**是否一直有效可读？

### 背景参考（thprac 已确认的邻近事实）
- th13 的 pause 是 `[PauseInf(0x4c2194)]+0x60` 的 bit4（掩码 `0x10`），**th14 同类对象在 thprac 里尚无既有定义**，需要从零定位。
- 建议切入点：引擎的 `pause.cpp` 会有 `"Pause"` / `"UnPause"` trace 字符串与 `PauseInf` 构造/析构串；从这些字符串的绝对地址反查引用它的函数，再在该函数里找 `or dword ptr [reg+off],0x10` / `and dword ptr [reg+off],0xffffffef`。

### 结论（2026-09-30）
**`[0x4db558] + 0x80` 的 bit4（掩码 `0x10`），4 字节。`0x4db558` 是指向堆对象（PauseInf）的静态指针变量，必须二级读。**
- `& 0x10 != 0` ⇒ 暂停菜单打开（冻结）
- `& 0x10 == 0` ⇒ 未暂停

完整证据链见报告 §1。

## 2. "非 replay"标志

### 目标
需要判断"**当前是否正在播放 replay（回放）**"。

注意区分：thprac 里已有的 replay 相关读取（如各作 `REPLAY_MGR_PTR → +0x1c → +0xc`，数据头字段）是**读取 replay 数据头里的字段**，**不是**"实时是否在回放"这个状态量。不要拿它当答案。

### 需要确认的问题
1. 游戏把"当前处于 replay 播放中"存在哪个地址？给出地址或指针链。
2. 取值语义：什么是"正在回放"，什么是"正常游玩"？
3. 该状态从**何时开始**置位、**何时清除**？（例如：从 replay 菜单选定播放时置位，回到标题时清除。）
4. 在 replay 播放期间，"gamemode"是否也为真？我们需要确认两个判据是**独立**的（否则单靠 gamemode 无法排除回放）。
5. 该地址在任意时刻是否都有效可读？

### 背景参考
- th13 的 replay 是 `[ReplayMgr(0x4c22c8)]+0x10 == 1`（`+0x10` = mode，`0` = 录制、`1` = 回放），且游戏自带访问器 `0x413c60: mov ecx,[0x4c22c8]; xor eax,eax; cmp dword ptr [ecx+0x10],1; sete al; ret`。**th14 应优先找形状完全相同的"自带 `IsReplay()` 访问器"**。
- 引擎的 `replay.cpp` 有 `"initialize ReplayInf"` / `"shutdown ReplayInf"` / `"replay/%s"` / `"th14_%.2d.rpy"` 等字符串可作锚点。

### 结论（2026-09-30）
**`[0x4db688] + 0x10`（ReplayManager 的 mode 字段），4 字节。`0x4db688` 是静态指针变量，必须二级读。**
- `== 1` ⇒ 正在播放 replay
- `== 0` ⇒ 正常游玩（录制中）
- 其它值 ⇒ 清理/关闭路径，非回放

游戏自带访问器 `0x41d640` 直接给出判据，完整证据链见报告 §2。

## 3. "关卡进行中"标志（gamemode）

### 目标
需要判断"**当前是否处于关卡进行中**"（排除标题 / 菜单 / 选人 / 结算 / 剧情对话）。

### 背景参考
- thprac 既有：`thprac/src/thprac/thprac_th14.cpp:16` 的 `PLAYER_PTR = 0x4db67c`（玩家对象指针）。th13 的 gamemode 就是 `*(u32*)0x4c22c4（PLAYER_PTR） != 0`，可优先复用同一形态。

### 需要确认的问题
1. `0x4db67c` 是否确实是"每关创建、关卡结束销毁"的堆对象指针？（给出赋值点与清零点）
2. 在标题画面 / 菜单 / 选人下它是否为 0？
3. 在 replay 播放期间它是否也非 0（若是，则 replay 必须由 §2 独立排除）？

### 结论（2026-09-30）
**`*(u32*)0x4db67c != 0`（单级读）。`0x4db67c` 即 thprac 既有 `PLAYER_PTR`。** 创建点 `0x44c44a`（分配 `0x184c0` 字节的 Player 对象后写入）、清零 `0x44d17a`。完整证据链见报告 §3。

## 4. 三态验证（必须做，且必须记录）

任何候选地址在被采纳前，都必须通过下面的验证。**请在报告里附上实际观测值。**

在"正常游玩 / 打开暂停菜单 / 播放 replay"三种状态下，分别读取候选地址并记录取值：

| 状态 | 期望 |
| --- | --- |
| 标题画面 / 菜单 / 选人 | gamemode 判据不成立（不计时） |
| 关卡内正常游玩 | 三个判据**全部成立**（计时） |
| 关卡内按 Esc 打开暂停菜单 | pause 判据不成立（暂停不计时） |
| 播放 replay 期间 | replay 判据不成立（回放不计时） |

三种状态下取值必须**互不相同**且符合各自判据，否则该地址不可用。

thprac 侧已有一段现成的三态探针做法可以参考：`docs/gametime/gametime_plan.md` §1.7 提到的调试读数面板，会直接显示三个标志位的原始读数。

> **本机（macOS）无法运行游戏**，故本轮只做静态反汇编定案，三态验证清单已集中列入 `docs/gametime/gametime_runtime_verification.md`。

## 5. 交付格式

结论已回填到 **`docs/th14/th14_re_disasm_report.md`**。要求：

- 同时给出：**静态地址（或指针链）**、**判据表达式**、**取值语义**、**三态验证的实际观测值（待补）**。
- 所有地址统一用**静态偏移**表述。th14 固定基址 `0x400000` 且不重定位，所以绝对 VA 与 RVA 可互相直接换算（`RVA = VA - 0x400000`）。
- 若发现本文档中的假设/地址有误，直接指出并给出修正。
- 若某个量**确认不存在**，也请明确说明，并给出替代方案。

## 6. 工具与流程提示

- 逆向方法沿用 th13 报告 §5 的 **capstone 只读反汇编**（比开 Ghidra 轻）：解析 PE 节表 → `va2off` → 用 `"Pause"` / `"UnPause"` / replay 串的绝对地址在整文件里搜 LE 字节反查引用 → 在函数入口处反汇编整函数定位 `or/and [reg+off],0x10` 与 `cmp [reg+0x10],1`。
- 坑：`.text` 线性反汇编会因内嵌数据/跳表**早期失步**。可行做法是先在**函数入口处**（`int3` 填充后的第一个字节）反汇编，或先做"原始字节搜索 + 局部对齐重解码"。
- 相关既有资料：`thprac/src/thprac/thprac_th14.cpp` 顶部地址 enum、`docs/th13/th13_re_disasm_report.md`（同构参照）。
