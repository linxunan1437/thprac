## 2. Q1 当前 sub：索引还是指令指针？—— ✅ **已答**

**答**：**「指令地址（指针）」**，**不是 sub 索引**。`ip = *(u32*)(T + 0x004)`（T = 执行对象），指向 ECL 文件缓冲内的当前（下一条待执行）指令**绝对地址**；`0` = 线程结束。**本作不存在 subIdx 层**（与 th15–th18 的 `thread+4 = 索引` 不同；**与 th13 / th14 同类**）。
- 判据 / 写入点（`0x413448`/`0x467122`/`0x467409`/`0x4671F9`/`0x468BF3`/`0x468C24` 等）/ 反汇编片段：报告 §2。
- 「地址 → 当前 sub」的反查方法（按 `table[i].+4+0x10` 建排序区间表）：报告 §2.3。

## 3. Q2 sub 表：索引 → 名字/起始 —— ✅ **已答**

**答**：`mgr = *(u32*)0x4B43DC` → `res = *(u32*)(mgr+0x64)` → `count = *(i32*)(res+8)` → `table = *(u32*)(res+0x8C)`（项 **8B**，`+0` = 名字 `char*`、`+4` = sub 数据基址，**首指令 = `+4+0x10`**）。
访问器：`FUN_0040E8F0`（名字）/`FUN_0040E920`（count）/`FUN_0040E930`（res）；加载器 `FUN_004692E0`（SCPT `0x54504353`，`res+0xC+slot*4` = 文件缓冲）；按名查表 `FUN_004694F0`（二分）。
- 反汇编证据：报告 §3.1–§3.4。

## 4. Q3 函数栈 —— ✅ **已答**

**答**：**存在可遍历的显式子调用栈**。基址 `T+0x08`，SP = `*(u32*)(T+0x1008)`（0 = 空栈），**帧长 `0x0C`**，帧内 `+0x00` = 旧 SP / `+0x04` = 时间 / `+0x08` = **调用者指令地址**。压帧 = `call` 处理器 `FUN_00466F00`；弹帧 = `ret`(opcode `0x0A`) @ `0x4671CD`。
- **⚠️ 本作例外**：段落 sub 多为 **async 派生线程**（opcode `0x0F`），**各有独立栈**，跨线程**不构成调用链** ⇒ Q3 仅作逆向事实保留（不参与 Q9 判定，与总括 §6 Q9 一致）。
- 反汇编证据：报告 §4。

## 5. Q4 主线宿主捕获点 —— ✅ **已答**

**答**：捕获点 = **`0x4228BE` / `0x4229D2`**（各 **5B** EHOOK），命中时 **`EAX` = 主线 ECL 宿主 H**（宿主工厂 `FUN_00412990`，`malloc(0x27B8)`，`ret 8` 前 `mov eax, ebp`）。`"main"` @ `0x49FE14`（全程序唯一引用点，两处均在 `FUN_004227C0`）。
- 宿主工厂内 `T+4 = FindSubByName(res, "main")` @ `0x413448`。
- 静态兜底：宿主链头 = `mgr+0x68`（尾 `mgr+0x6C`、计数 `mgr+0x70`），节点 = `H+0x12C0`（**节点 `+0` = H**）⇒ `H = *(u32*)(*(u32*)(mgr+0x68))`。⚠️ 宿主工厂共 10 个调用点，只有上述两处传 `"main"` ⇒ **推荐用捕获点**。
- 反汇编证据：报告 §5。

## 6. Q5 解释器命中点与寄存器语义 —— ✅ **已答（本次硬骨头，全新自找）**

**答**：**`0x4671A0`**（`8B 77 04` + `8A 46 0A`，**6B** EHOOK）：
```asm
004671a0  8b7704            mov   esi, dword ptr [edi + 4]   ; ★ 命中：EDI = 执行对象 T，[T+4] = 当前指令
004671a3  8a460a            mov   al, byte ptr [esi + 0xa]
```
- **命中寄存器 `EDI` = 执行对象 T**；所在函数 = **`FUN_00467170`**（`0x467170`，体 `0x467170`–`0x468C37`）= ECL 主解释器（每帧逐指令步进）；入参 `EAX` = T；返回 `0` = 本帧到此为止、`−1` = 脚本结束。
- opcode 跳表 `0x468C38`（62×4B）、字节映射 `0x468D30`（`0x5A` B）、上界 `0x59`（`> 0x59` → `0x468BD9` 虚调用）。
- 调用链：`FUN_00468D90`（宿主线程链驱动器）→ `call FUN_00467170`（每帧每线程一次）。
- ⚠️ 「纯等待（时间未到）」时不经过此点，且会**对所有线程**命中 ⇒ 须用宿主 H 过滤。**推荐仍以 §5 的捕获点 + 帧间稳定态读取为主，此点作备选。**
- **⚠️ 对原「建议切入点」的更正**：本报告实测更短的路径为「SCPT 魔数 → 加载器 → res/表」+「`"main"` 字符串 → 宿主工厂」+「`disp 0x1008` 密集区 → VM/spawn/驱动器」，而非从 `THSectionPatch` 数据区链反查解释器。详见报告 §6.4。
- 反汇编证据：报告 §6。

## 7. Q6 名字来源 —— ✅ **已答**

## 9. Q8/Q9 练习跳转补丁影响 + 段落判定口径 —— ✅ **已答**

> **Q9（段落判定口径）**：**已定案为「路过式 checkpoint（latch）」**（见总括 §6 Q9）——经过白名单函数即置值、不在表内 no-op（不回退 `main`）。

**Q9 答**：走 latch 口径；**但本作的「读取面」必须扩大**：th12 的段落 sub 由 `opcode 0x0F`（`@MainSubNN() async`）**派生为独立线程**，主线线程的 `T+4` **全程停留在 `main`** ⇒ **只读主线线程无效，必须遍历宿主线程链 `H+0x1030`（节点 `{+0 = T, +4 = next, +8 = prev}`），对每条线程取 `T+4` 映射为 sub 名，任一 ∈ 白名单即置值。**
**每 checkpoint 只登记 1 个入口 sub**（含 async 落点）。**⚠️ 段落入口白名单尚未枚举**（阶段 E3/E4）：`THStageWarp` 的 `ECLJumpEx(…, dest, …)` 的 **`dest` 精确落在 `main` 内一条 `opcode 0x0F` 指令上，该指令内嵌的名字即段落入口 sub**（stage1/stage2 抽验 8/8 命中，见报告 §10.4）；完整枚举**未做**。

**Q8 答**：练习补丁**不影响** sub 判读。`ECLJump/ECLJumpEx` 只把 `goto`(`opcode 0x0C`) 写进运行期缓冲，`goto`(case @ `0x4673FC`) **只改 `T+0`(时间) 与 `T+4`(ip)**，不触碰 sub 表与任何「当前 sub」旁路字段。⚠️ `ECLCallSub` 是死代码（§1）。
- 反汇编证据：报告 §9 / §10。
